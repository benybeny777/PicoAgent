# Claude設計レビュー

## 必須ゲート

1. 変更対象と現在の挙動を必要最小限の検索で確認する。
2. 実装前に、次の情報を1つの短い質問へまとめてClaude CLIへ渡す。
   - ユーザー要件
   - 現在の挙動と根本原因
   - 提案する設計と変更範囲
   - 互換性、安全性、リソース解放、検証の懸念
3. Claudeへ、重大な欠陥、過不足、代案、必要な回帰テストを日本語で指摘させる。
4. 回答をコードとルール正本へ照合し、採用・一部採用・見送りを理由付きで決める。Claudeの回答を無条件に採用しない。
5. 設計が変わる指摘を採用した場合は、変更後の設計を確定してから実装する。
6. 実装中に範囲または設計を大きく変えた場合は、変更部分を再レビューしてから続行する。
7. 結果を `docs/REVIEW-LOG.md` へ残す。Claudeの提案、採否、理由、検証条件を分けて書く。

## 呼び出し

テキストだけの設計相談には `claude -p --output-format text "<質問>"` を使う。質問が長くなりすぎないよう、対象ファイルの全文ではなく関係する構造と案を要約する。機密値、APIキー、無関係なファイルを渡さない。

## 停止と再試行

- 90秒以内に応答しない場合は残ったClaude CLI子プロセスを特定して回収し、質問を短くして1回だけ再試行する。
- 再試行では論点を減らし、利用可能なら軽量Claudeモデルを指定する。
- 2回とも応答しない、CLIが未導入、認証できない場合は設計レビュー未完了として実装を開始しない。`docs/REVIEW-LOG.md`へ保留理由を残し、ユーザーへ停止境界を報告する。
- 画像レビューは設計レビューと別ゲートにする。画像Readが停止しても、テキスト設計レビューの成功で代用しない。

## 完了条件

- Claudeの設計レビュー回答がある。
- 回答の採否と理由が `docs/REVIEW-LOG.md` にある。
- 採用した検証が成功し、見送った提案に理由がある。
