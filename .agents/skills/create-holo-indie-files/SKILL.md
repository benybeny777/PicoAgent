# holo Indie提出ファイルを作る

## 対象と保存先

- 作るファイルは、読み手が単独で理解できるGoogleスライドと、さくらみこ公式MMDだけを含むholo Indie審査版インストーラ。保存先は利用者指定のDriveフォルダ。応募フォーム送信や一般公開は別の明示指示がある場合だけ行う。
- スライドの作成に一時的なPPTXを使っても、PPTX・インストーラ・分割ファイルをGitへ追加しない。提出ファイルではなく、この生成スキルをプロジェクトに残す。利用者や別エージェントの既存変更を巻き戻さない。

## 動画付き企画書

1. 文面の正本 `docs/HOLO-INDIE-PLAN.md` と `tools/holo-indie-deck/README.md` を読む。企画書として対象ファン・体験・審査で相談したい点が単独で通じるようにし、口頭発表用の台本へ戻さない。
2. 必要なら `tools/holo-indie-deck/build.js` で下書きPPTXを生成し、DriveでネイティブGoogleスライドへ変換する。実画面・動画の再撮影が必要な場合だけ、同じディレクトリの `capture-current.mjs`（動画も撮る場合は `--video`）を使う。ミニゲーム結果画像 `holo-indie-result.webp` を撮る専用スクリプトは無いため、ゲーム画面を変えた場合は現行UIで撮り直す。さくらみこ公式MMDのモデル本体や利用者設定は変更しない。下書きPPTXは提出せず、Gitにも入れない。
3. さくらみこのAivis音声付きMP4と、ひよりの無音Live2D動作例を同じDriveフォルダへアップロードする。変換で動画が静止画になった箇所はGoogleスライドのDrive動画に置き換える。表紙とキャラクター説明ページの動画オブジェクトの参照先を読み戻す。ひよりは旧UI撮影の動作例であり、審査版への同梱キャラではないと明記する。
4. ファイル名と資料内に「動画はスライドショーで▶を押して再生」と明記する。編集画面・PDFの静止表示やAPI上の動画オブジェクトだけを動作確認とせず、スライドショーでみこの動画を再生して映像・時間・音声の進行を確認する。自動再生は実画面で確認できた場合だけ報告する。
5. Googleスライド、さくらみこのMP4、インストーラが指定フォルダにあることを読み戻す。提出ファイルをGitに残さない。

## 審査版インストーラ

1. 既存のインストーラを渡す依頼なら、`temp/holo-indie-review-installer/` の実体、版、更新日時、SHA-256と生成設定を確認する。新規ビルドの依頼なら、`holo Indie審査版インストーラをビルド.bat` または `scripts/build-holo-indie-review-installer.ps1` を使う。古いチェックアウトを許す `-AllowStale` を安易に付けない。
2. ビルドスクリプトが公式MMDの出所と利用条件、Aivisの同梱と読み上げ有効、本人音声モデルを含めない設定、通常版と分離した保存先を確認する。生成したWindows実行ファイルの版、MZヘッダー、容量、SHA-256を確認する。実インストール・新規Windows環境での表示と仮音声の再生を試していなければ、その境界を明記する。
3. 指定先へ実行ファイルを単体でアップロードする。連携ツールの容量制限で不可能な場合は、別の認証済みアップロード経路を確認する。単体で置けないときだけ、各ファイルが制限以下になるよう分割し、同じフォルダに復元手順とSHA-256照合方法を置く。分割前後のハッシュと保存先の各ファイルを確認し、単体で置けなかったことを報告する。

提出ファイルの説明には、同梱キャラクターがさくらみこMMDモデル1体であること、ひよりは旧UI撮影のLive2D動作例で審査版に同梱しないこと、インストーラが限定共有用であることを保つ。
