## Windows向けCodex Process Jobs開発ツール

Codex Process Jobsの現行プラグインはWindowsを非対応としており、モデル取得、依存導入、ビルド、ベンチマークなど60秒を超える有限処理をWindowsで永続追跡できない。PicoAgentの開発用ツールとして、同等の操作契約を持つWindows対応プラグインを別PRで実装する。この項目を追加するPRでは設計だけを確定し、プラグイン本体は後続コミットで進める。

| 項目 | 設計 | 完了条件 |
|---|---|---|
| 配置 | `plugin-creator`の正規手順で`.codex-plugin/plugin.json`を持つリポジトリ管理プラグインとして作る。製品バイナリや配布物へは同梱しない | Codexの開発環境から導入・更新でき、PicoAgent本体のビルドと実行へ影響しない |
| 起動 | 有限の前景コマンドを非対話で開始し、ジョブID、PID、作成時刻、実行ファイル、引数、作業ディレクトリを永続記録する | Codexやターミナルを閉じても処理が継続し、後続セッションから同じジョブを特定できる |
| Windows所有権 | Windows Job Objectへ子孫プロセスを所属させ、PID再利用を作成時刻・実行ファイル・コマンドラインで拒否する | 名前一致の一括停止を行わず、対象ジョブの子孫だけを終了・回収できる |
| 記録 | 標準出力・標準エラー・終了コード・開始終了時刻を容量上限付きで保存し、`status`、`tail`、`result`相当を提供する | 実行中、成功、失敗、取消を区別し、ログ肥大化や秘密値の記録を防ぐ |
| 中断と復旧 | 通常終了要求から猶予後の強制終了へ進み、中断中にCodexが終了しても次回操作で状態を再評価する | 親だけ終了して子が残る状態、完了済みを実行中と誤認する状態、別プロセスを停止する状態がない |
| 通知 | 完了通知を利用できる場合だけ送信し、通知不能でも永続記録から結果を取得できるようにする | 通知の成否をジョブの成否と混同せず、再接続後に結果を回収できる |
| 検証 | 短時間処理、長時間処理、大量出力、失敗、取消、子プロセス生成、Codex再起動、PID再利用を自動試験する | Windows実機で全経路を通し、処理後に管理対象プロセスとハンドルが残らない |

実装時は既存Codex Process Jobsとのコマンド名と結果形式の互換性を優先し、Windows固有差分だけを分離する。上流プラグインへWindowsバックエンドを追加できる場合は重複実装を避け、独立プラグインにする場合も移行可能な状態形式にする。

## 責務が集中したファイルの再評価

肥大化した対象は、状態の所有者、副作用、公開インターフェース、独立して機械検査できる境界を棚卸しする。分割後の依存が減る対象だけを分け、一体の方が効率的なら維持する。挙動変更と混ぜず、各段階を独立したPRで行い、公開中のPRと同じファイルを同時に変更しない。

| 対象 | 現時点の判断 | 再評価・着手条件 |
|---|---|---|
| `ui/settings.js` | 中央の設定スナップショット、未保存判定、保存処理は一体で維持する。目覚まし・スケジュールの専用フォームとJSON整形は独立していたため分離済み | スキル一覧、キャラクター設定、診断表示のいずれかが、中央状態を所有せず入力と描画だけの小さいAPIにできる場合だけ追加分割する |
| `ui/renderer.js` | 責務が複数あり分割候補 | PR #168の統合後、キャラクター描画・リップシンク、通知・目覚まし、会話入力の状態所有者とイベント境界を確認する |
| `src-tauri/src/commands.rs` | Tauri commandの入口は集約する価値があるが、業務処理まで同居している箇所は分割候補 | PR #168の統合後、設定、キャラクター、追加機能、会話についてcommandを薄い委譲にできる責務だけ移す |
| `xtask/src/assets.rs` | キャラクター同期、UI配信ビルド、管理プロセス回収は副作用と検証が異なるため分割候補 | 共有する配布パス判定を複製せず、各処理を独立テストできる境界を決めてから着手する |
