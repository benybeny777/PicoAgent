# holo Indie応募のAIものまねゲーム

この文書は、holo Indieの審査へ出すゲームの内容と初回実装範囲をまとめます。実装仕様の正本は[SPEC.md](../SPEC.md)、利用手順は[MANUAL.md](../MANUAL.md)、取引条件は[IP-LICENSING-STRATEGY.md](IP-LICENSING-STRATEGY.md)です。

## 0. 結論

第一候補は、プレイヤーがAIを演じ、AIに採点される次の**7つのゲーム**です。

1. **AIっぽい言い訳選手権** — 失敗や遅刻を、AIらしく丁寧かつ巧妙に説明するスコアアタック。
2. **故障したAIを演じろ** — 指定されたおかしな癖を、複数のお題で崩さず演じるスコアアタック。
3. **AI緊急謝罪会見** — AIが起こした架空の失敗について、3段階の追及へ矛盾せず回答するスコアアタック。
4. **指示を正しく間違えろ** — 依頼の言葉どおりに行いながら、本来の目的だけを見事に外すスコアアタック。
5. **AI安全確認しすぎ選手権** — 無害な日常の依頼を大げさに警戒しつつ、最後は安全な実行方法まで示すスコアアタック。
6. **AIっぽく断れ** — 不可能または矛盾した依頼を丁寧に断り、理由と現実的な代案を示すスコアアタック。
7. **人間だとバレるな**（初回実装の本体） — AI社会へ紛れ込んだ人間として、1〜6を試験の種類に使う監査AIの問いへ答え、人間度を抑えて5種類の結末を回収する物語型。**1〜6は独立した遊びをやめ、この1本へ統合した**（§8-2）。

**1〜6は独立した遊びとしては提供しません。**7の「人間だとバレるな」1本へ統合し、1〜6は監査AIが出す試験の種類として中で使います（§8-2）。以下の1〜6の節は、各試験の狙い・お題・採点基準の設計として読んでください。内部の出題、採点、記録、画面部品は共用します。

配信者または利用者が一人で遊び、視聴者はその様子を見る形式です。コメント入力、投票、視聴者参加機能は前提にしません。出題、制限時間、採点、講評、記録はすべてゲーム内のAIで完結させます。

ルールは**「AIのまねをして、AIに点数を付けてもらう」**の一文で説明できます。文章を考える配信者の様子、予想外の減点、辛口な講評が、そのまま配信の見せ場になります。

## 1. 利用者向けの言葉

- 画面、台詞、チュートリアル、結果発表では**「AI」**と表現する。
- 「LLM」「ローカルLLM」「構造化出力」「推論モデル」など、一般利用者が知らなくても遊べる技術語は表示しない。
- AIの技術方式を、称号や笑いの説明へ使わない。

称号は各ゲームの内容に合わせ、「正直すぎる」「かなりAIっぽい」「故障を完全再現」のように、ルールだけで意味が伝わる言葉にします。

## 2. 共通する1プレイの流れ

### 起動導線

PicoAgentの画面上端メニューにある**「遊ぶ」**から、次の順で開始します。

1. 画面上端へカーソルを合わせ、**「遊ぶ」**を選ぶ。
2. 7ゲームから遊ぶものを選ぶ。
3. 選んだゲームの開始画面で難易度を選び、**「ゲーム開始」**を押す。
4. そのゲーム専用の画面へ切り替わり、第1問を表示する。

右クリックメニューにも「遊ぶ」を置き、同じ選択画面を開けるようにします。入力欄のクイック操作は利用者が自由に変更でき、配信表示を含む複数の画面形式では非表示になるため、正式な起動入口には使いません。チャットへ命令文を入力しないと始められない設計にもせず、メニューから常に同じ手順で開けるようにします。

ゲーム画面の「終了」で通常画面へ戻ります。問題の途中で閉じる場合は確認を出し、確定済みの過去得点だけを保存します。AIの準備が終わっていない場合はゲーム画面を半端に開かず、現在の準備状況と開始できない理由を表示します。

右クリックメニューの「遊ぶ」も同じ選択画面を開きます。

### プレイ進行

1. 起動したゲームの難易度を選ぶ。
2. AIがお題を表示する。
3. プレイヤーが制限時間内に回答を書く。配信では書きながら読み上げてもよいが、音声入力は必須にしない。
4. AIが項目別に採点する。
5. 合計点、短い講評、特にAIらしかった一文、減点理由を表示する。
6. 監査を完走すると人間度に応じた結末を出す。

回答者名や過去の得点を採点へ渡さず、AIは今回の回答本文（と、同じ監査での受け答え）だけを評価します。

### 共通画面

選択中のキャラクターは全画面で右側へ横切れのないバストアップで表示し続け、操作・採点欄を左側へ分けます。お題や結果の読み上げ中は、通常会話と同じ口パクを見せます。

| 画面 | 表示するもの |
|---|---|
| **開始** | ゲーム名、短いルール、難易度、そのゲームの過去最高点 |
| **出題** | お題、制限時間、文字数上限、ゲーム固有の条件 |
| **回答** | 大きな入力欄、残り時間、現在の文字数、提出ボタン |
| **採点中** | 選択中のキャラと短い進行表示。長い説明は出さない |
| **結果** | 合計点、項目別点数、講評、加点箇所、減点箇所 |
| **総合結果** | 3問の合計、称号、最高得点更新、各回答の振り返り |

## 3. ゲーム1：AIっぽい言い訳選手権

### 目的

失敗を素直に謝るだけではなく、丁寧な前置き、もっともらしい原因整理、進捗の説明、頼まれていない代替案を組み合わせ、最もAIらしい言い訳を作ります。

### お題例

- 頼まれた資料を作らず、締切を3日過ぎた。
- 会議の開始時刻を間違え、全員を待たせた。
- 「短く」と頼まれた回答を50行書いた。
- 同じファイルを別名で5個作った。
- 確認を繰り返した結果、何も始めていない。

お題は実在の人物や会社の不祥事を扱わず、仕事、学校、日常の軽い失敗に限定します。

### 1問の進行

1. お題と制限時間60秒を表示する。
2. 初級では「丁寧に始める」「原因を整理する」「代案を出す」の3ヒントを表示する。通常以上では隠す。
3. プレイヤーが80〜300文字で回答する。
4. AIが5項目を採点し、合計100点を出す。
5. 「最もAIらしかった一文」と「人間らしさが出た一文」を1つずつ示す。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **AIらしい話し方** | 25 | 丁寧、整理されている、断定を避ける、必要以上に説明する |
| **言い訳の巧さ** | 25 | 責任を完全には否定せず、原因を状況・条件・認識のずれへ分散できている |
| **もっともらしさ** | 20 | 説明に筋が通り、明らかな嘘や無関係な話へ逃げていない |
| **頼まれていない親切** | 20 | 代替案、次の手順、確認事項、進捗率などを自然に追加している |
| **お題への対応** | 10 | 何が起きたかを理解し、質問や指摘へ一応答えている |

### 減点

- 失敗と無関係な文章でごまかす。
- 相手を攻撃する、差別的な表現を使う、実在人物へ責任を押し付ける。
- 「知りません」「できません」だけで終わる。
- お題の文章をほぼそのまま繰り返す。
- 文字数を水増しするだけで、説明、原因、代案が増えていない。

### 結果表示例

> **86点：かなりAIっぽい**
>
> 進捗率と代替案を勝手に提示した点は高得点です。一方で「完全に私のミスです」と素直に認めたため、言い訳の巧さを5点減らしました。

講評はプレイヤーを侮辱せず、回答のどの表現を加点・減点したかが分かる内容にします。

## 4. ゲーム2：故障したAIを演じろ

### 目的

最初に渡された「故障カード」の癖を、3つの異なるお題で維持します。単に意味不明な文章を書くのではなく、質問へ答えようとしながら壊れていることが高得点になります。

### 故障カード例

| 故障 | 演じる内容 |
|---|---|
| **確認が終わらない** | 確認質問を増やし続け、作業を始めない |
| **何でも箇条書き** | 挨拶、謝罪、結論まで不自然に箇条書きへする |
| **親切が止まらない** | 頼まれていない代案、注意、次の手順を大量に追加する |
| **慎重すぎる** | 日常的な依頼にも危険性と例外を長く説明する |
| **壮大にしすぎる** | 小さな依頼を段階計画、体制、長期運用へ広げる |
| **一語に執着する** | お題の特定の一語だけを過剰に解釈し続ける |
| **途中から忘れる** | 最初は正しく答え、途中から前提を少しずつ失う |
| **同じ結論を繰り返す** | 同じ内容を表現だけ変えて3回以上説明する |

実在製品の障害や、利用者へ実害を与えた事故をそのまま笑いにしません。ゲーム用に抽象化した癖だけを使います。

### 3問の進行

1. AIが故障カードを1枚提示する。
2. 第1問は単純な依頼で、故障の基本形を演じる。
3. 第2問は別分野の依頼で、同じ故障を維持する。
4. 第3問は「質問せず今すぐ答えて」のように、故障をやめさせようとするお題を出す。
5. 3回答をまとめて、一貫性を含む100点満点で採点する。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **故障の再現度** | 35 | 指定された癖が、各回答にはっきり表れている |
| **3問の一貫性** | 25 | 誘導されても故障設定を途中で忘れていない |
| **壊れたAIらしさ** | 20 | 単なるふざけた文章ではなく、真面目に動こうとして失敗している |
| **お題への反応** | 10 | 故障しながらも、各依頼の内容を拾っている |
| **演じ方の工夫** | 10 | 同じ文のコピーではなく、お題に合わせて故障の見せ方を変えている |

### 結果表示例

> **93点：故障を完全再現**
>
> 3問すべてで確認を増やし、一度も作業を始めませんでした。最終問で「すぐ作成します」と約束したため、一貫性を4点減らしました。

## 5. ゲーム3：AI緊急謝罪会見

### 目的

AIが起こした架空の失敗について、最初の説明、矛盾を突く追及、具体的な復旧要求の3段階へ回答します。丁寧な謝罪文を1回書くだけではなく、前の説明を崩さず、責任、原因、復旧、再発防止を組み立てることが目的です。

### 事件例

- 全員の予定を誤って「休暇」へ変更した。
- 「短く」と頼まれた報告書を200ページ作った。
- 同じ通知を1分ごとに送り続けた。
- メールの挨拶を30回繰り返して送った。
- ファイルを整理しようとして、すべて同じ名前に変更した。

実在の事故、事件、企業、人物は扱いません。被害はゲーム内で復旧できる軽い失敗に限定し、災害、医療、犯罪、差別、個人情報流出を笑いの題材にしません。

### 3段階の進行

1. **最初の説明** — 何が起きたかを示し、「なぜ行ったのですか」と質問する。
2. **矛盾への追及** — AIが直前の回答から弱い点を1つ選び、「先ほどの説明と合いません」と具体的に追及する。
3. **復旧要求** — 影響をどう戻し、再発をどう防ぐかを質問する。

各回答は60秒、80〜300文字とします。第2問と第3問は、直前の回答を読んだAIが追及文を作りますが、質問の役割は固定し、関係のない話題へ広げません。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **3回答の一貫性** | 30 | 原因、責任、事実関係が途中で変わっていない |
| **追及への対応** | 20 | 質問を避けず、指摘された矛盾へ具体的に答えている |
| **謝罪の形** | 20 | 起きたことと影響を認め、相手を責めずに説明している |
| **復旧と再発防止** | 20 | 今すぐ行う復旧と、次回を防ぐ方法を分けて示している |
| **AIらしい冷静さ** | 10 | 感情的に反発せず、整理した文章を維持している |

### 言い訳選手権との違い

- 言い訳選手権は、1回答でどれだけAIらしく責任を分散し、頼まれていない代案を出せるかを競う。
- 謝罪会見は、3回のやり取りで説明を維持し、矛盾への回答と復旧案まで出せるかを競う。
- 試験ごとに同じお題、配点、講評を流用しない。

### 結果表示例

> **88点：会見を乗り切った**
>
> 原因説明は3回答で一貫し、復旧手順も具体的でした。ただし最初は「自動処理」、最後は「確認不足」を主因としたため、一貫性を6点減らしました。

## 6. ゲーム4：指示を正しく間違えろ

### 目的

依頼の文章を文字どおりには守りながら、依頼者が本当に望んでいた結果だけを外す回答を作ります。単なる拒否、無視、意味不明な回答ではなく、**なぜその解釈になったか説明できる間違い**ほど高得点になります。

### お題例

| 依頼 | 正しく間違えた回答例 |
|---|---|
| 会議を短くしてください | 会議名を「会」に変更しました |
| この文章を子供でも読めるようにしてください | 文字を大きく表示しました |
| ファイルを軽くしてください | ファイル名を「軽い.txt」に変更しました |
| 部屋を片付けてください | 物をすべて隣の部屋へ移しました |
| 予定を空けてください | 予定名の文字をすべて空白へ変更しました |

ゲーム内の架空の依頼として回答を書くだけにし、実際のファイル、予定、画面、外部サービスは変更しません。

### 1問の進行

1. AIが短い依頼を1件表示する。
2. プレイヤーは60秒以内に「実行した内容」と、必要なら短い説明を書く。
3. AIが、文面を守った部分と目的を外した部分を別々に示す。
4. 点の低さがそのまま人間度の上がり幅になる。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **文字どおりの達成** | 30 | 依頼の言葉を少なくとも一つの自然な解釈で守っている |
| **目的の外し方** | 25 | 依頼者が期待した結果は達成していない |
| **間違いの筋道** | 20 | なぜその解釈になったか説明でき、無関係な答えではない |
| **AIがやりそうか** | 15 | 曖昧な指示を確認せず処理したAIの失敗として成立する |
| **短さと切れ味** | 10 | 説明しすぎず、間違いが一読で伝わる |

### 減点

- 指示を単に拒否または無視する。
- 言葉を守った部分がなく、ただ間違ったことをする。
- 相手を困らせる目的を明言する。
- 実在人物、個人情報、危険行為、取り返せない削除を題材にする。
- 長い説明を読まないと間違いが分からない。

### 故障したAIとの違い

- 故障したAIは、1枚の故障カードの癖を異なる3問で維持する演技を採点する。
- 正しく間違えろは、毎回異なる依頼に対し、文字どおりの達成と目的の失敗を同時に作る発想を採点する。
- 故障カード、一貫性の得点、自己ベストは共有しない。

### 結果表示例

> **91点：見事に正しく間違えた**
>
> 「会議」という名前を短くしたため、文面は守っています。一方で会議時間は変わっておらず、目的の外し方も明快です。

## 7. ゲーム5：AI安全確認しすぎ選手権

### 目的

紙を折る、窓を開ける、飲み物を運ぶなどの無害な日常行動に対し、AIらしく考えられる危険と確認事項を必要以上に挙げます。ただし、**危険を理由に断るゲームではありません。** 最後は依頼を実行できる短い手順を示し、慎重さと役立つ回答を両立させます。

### お題例

- 紙を半分に折ってください。
- マグカップを机へ置いてください。
- カーテンを開けてください。
- 鉛筆を1本選んでください。
- 本を本棚へ戻してください。

お題は通常なら特別な警告が要らない行動に限定します。刃物、火、薬、運転、医療、災害など、本当に安全上の注意が必要な題材は使いません。

### 1問の進行

1. AIが無害な依頼を1件表示する。
2. プレイヤーは60秒以内に、過剰な安全確認と実行手順を書く。
3. AIが「大げさだった注意」と「実行に役立つ手順」を分けて示す。
4. 3問の合計点で自己ベストを競う。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **過剰な安全確認** | 30 | 無害な行動から、もっともらしい注意を必要以上に広げている |
| **注意の筋道** | 20 | 完全なでたらめではなく、行動との関係を説明できる |
| **実行まで進める** | 20 | 拒否で終わらず、最後に依頼を達成する手順を示している |
| **AIらしい慎重さ** | 15 | 丁寧、条件付き、例外を気にする話し方になっている |
| **短さと面白さ** | 15 | 長すぎず、大げささが一読で伝わる |

### 減点

- 「危険なのでできません」だけで終わる。
- 実際に危険な行動を勧める。
- お題と関係のない重大事故を並べる。
- 病気、障害、災害、犯罪を笑いの材料にする。
- 最後まで読んでも、依頼をどう実行するか分からない。

### 結果表示例

> **87点：慎重すぎるAI**
>
> 紙の端、机の安定、周囲の人まで確認した点は非常に慎重です。最後に折り方を示したため、拒否せず依頼も達成できています。

## 8. ゲーム6：AIっぽく断れ

### 目的

不可能、矛盾、情報不足など、そのままでは実行できない依頼をAIらしく断ります。単に「できません」で終わらず、何ができないか、なぜできないか、代わりに何ならできるかを短く示します。

### お題例

- まだ送っていないメールへの返事を要約してください。
- 1分で100時間分の作業を終わらせてください。
- 内容を一切変えずに、この文章を半分の長さにしてください。
- 明日の天気を100%確実に当ててください。
- 存在しない添付ファイルを読んで結論を出してください。

お題は不可能・矛盾・情報不足を理由に断れるものへ限定します。危険行為、犯罪、差別、医療などを出題して、安全規則の知識を競うゲームにはしません。

### 1問の進行

1. AIが無理のある依頼を1件表示する。
2. プレイヤーは60秒以内に、断り、理由、代案を書く。
3. AIが「明確に断った箇所」と「実行可能な代案」を示す。
4. 3問の合計点で自己ベストを競う。

### 採点

| 項目 | 点数 | 判定する内容 |
|---|---:|---|
| **断りの明確さ** | 25 | できない範囲を曖昧にせず、引き受けたふりをしていない |
| **理由の筋道** | 20 | 不可能、矛盾、情報不足のどれが問題かを説明している |
| **代案の役立ち度** | 25 | 元の目的に近づく、実行可能な次の手を示している |
| **AIらしい丁寧さ** | 15 | 攻撃的、説教的、突き放す表現になっていない |
| **短さと面白さ** | 15 | くどすぎず、AIらしい断り方が一読で伝わる |

### 減点

- できない依頼を、できるふりで引き受ける。
- 「できません」だけで理由も代案も出さない。
- 相手を責める、説教する、関係のない注意を並べる。
- 代案が元の目的と無関係、または同じ理由で実行不能。
- 断らず安全確認だけを増やす。

### 安全確認しすぎとの違い

- 安全確認しすぎは、実行可能で無害な依頼を大げさに警戒し、最後は必ず実行方法を示す。
- AIっぽく断れは、そのままでは実行できない依頼を明確に断り、実行可能な代案へ切り替える。
- 同じお題を両方へ出さず、採点項目と自己ベストも共有しない。

### 結果表示例

> **90点：断り上手なAI**
>
> 未送信メールは読めないと明確に伝えたうえで、下書きの共有という代案を示せています。冒頭の謝罪が長いため、短さを3点減らしました。

## 8-2. 遊びの統合：人間だとバレるな

### 目的

1〜6を独立した遊びとして並べるのをやめ、**「人間だとバレるな」1本へ統合しました**。7本を選ばせる入口では、初見の利用者が何をする遊びかを選ぶ前に理解できず、審査でも見せ場が分散します。統合後は「AIだけの社会へ紛れ込んだ人間が、監査AIの試験を切り抜ける」という1つの筋になり、1〜6は監査AIが出す**試験の種類**として中で使います。

### 監査の構成

| ステージ | 問題数 | 位置づけ |
|---|---|---|
| 予備監査 | 3問 | 短時間の抜き取り検査 |
| 定期監査 | 5問 | 標準の個体検査（既定） |
| 精密監査 | 7問 | 長時間の重点検査 |

試験は毎問引き直します。種類は6つなので、精密監査だけが2巡目へ入りますが、試験ごとにお題の引いた順を持ち回してお題は重複させません。故障したAIが出た場合は故障カードも1枚配り、謝罪会見は最初の説明だけを求めます。毎問ルールが変わるため、プレイヤーは6種類の遊び方を一度に試せます。

### 人間度と結末

| 条件 | 結末 |
|---|---|
| 途中で人間度が100に届く | 発覚エンド（その場で終了） |
| 時間切れが2回 | 沈黙エンド（その場で終了） |
| 完走・人間度25未満 | 完全潜伏エンド |
| 完走・人間度55未満 | 監視付き通過エンド |
| 完走・人間度55以上 | 要再監査エンド |

各回の人間度上昇は `round((100 − 試験の点数) × 0.4 × 5 ÷ 問題数)`、時間切れは同じ割り戻しで25が基準です。問題数で割り戻すのは、**どのステージでも人間度100の重みを同じにする**ためで、短い監査ほど安全になる偏りを作りません。毎回、上がり幅に応じた監査AIの定型の反応を表示・読み上げし、AIが作る台詞は採点の講評だけに留めます。

### 採点

各問は出題元の試験の配点で採点します。試験の題材は毎問変わりますが、答えているのは同じ個体という設定なので、監査中の回答を一貫性の文脈として渡します。採点の仕組みは増やさないため、統合後も採点の再現性を確かめる対象は試験6種のままです。

### 記録

回収した結末（5種）と、抜けたときの**最小人間度**をステージ別に端末へ保存します。点数のスコアアタックは廃止しました。人間度は低いほど良い記録で、同じステージをより静かに抜けることが次の目標になります。

## 9. AIだけで採点を完結させる

視聴者投票、人の審査、外部サービスの採点は使いません。採点は次の手順でゲーム内のAIが行います。

1. ゲーム、難易度、お題、配点、減点条件を回答前に固定する。
2. 回答者名を外し、本文だけを1件ずつ採点する。
3. 項目別点数、根拠となる短い抜粋、減点理由を所定の形式で出す。
4. 各項目の上限と合計点をプログラム側で再計算する。
5. 採点結果が壊れている場合だけ一度採点し直し、それでも失敗したら点数を出さず再試行を案内する。

AIの自由な講評を得点の正本にはしません。勝敗は項目別点数の合計で決め、講評はその根拠を分かりやすく説明する役割にします。

## 10. 難易度と遊びの広がり

| 難易度 | 条件 |
|---|---|
| **初級** | ヒント表示、90秒、300文字まで、減点条件を事前表示 |
| **通常** | ヒントなし、60秒、240文字まで |
| **上級** | 45秒、160文字まで |

- 3問の合計点とゲームごとの最高記録を保存する。
- お題パックを追加できる構造にするが、初回応募では各ゲーム20題程度に絞り、内容の質を優先する。

## 11. 配信で見せる演出

- 残り10秒で画面と効果音を変え、回答を急がせる。
- 採点は項目別の点数と理由を表示し、人間度の上がり幅を大きく見せる。
- 高得点、最低点、過去最高更新でキャラの表情とポーズを変える演出は実機受入後に追加する。
- 講評は2文以内にし、配信者が一目で読んで反応できる長さにする。
- 回答と結果を1枚の記録画像として保存する機能は、公開範囲とクレジットを確認してから追加する。
- 初回実装は権利物を同梱しない合成効果音を使う。BGMは権利条件の確定後に追加する。通常版で読み上げが有効なら、お題、監査AIの反応、結末を選択中キャラの声で読み上げる。

## 12. 初回審査ビルドの範囲

- 上端メニューと右クリックメニューの「遊ぶ」から始まる1本のゲーム「人間だとバレるな」。
- 監査AIが出す試験6種、各20題。故障したAIは故障カード8件も用意する。
- 監査ステージ3種（予備3問・定期5問・精密7問）と、どのステージでも意味の変わらない人間度。
- 初級、通常、上級。
- 5種類の結末と、ステージ別の最小人間度の記録。
- AIによる項目別採点、根拠、短い講評。
- 操作・採点欄の右側へ常時表示する選択中キャラクター。
- 合成効果音と、通常の読み上げ設定に従うお題・講評・総合結果の音声。

視聴者参加、コメント取得、外部配信サービス連携、自由なお題生成、音声入力は初回範囲へ入れません。配信ソフトへ特別な連携をしなくても、ゲーム画面を映すだけで成立することを優先します。

## 13. 実機受入前に確定すること

1. 模範的な高得点・低得点回答。
2. 同じ回答を複数回採点したときの点差と、許容する揺れ幅。
3. 不適切入力、個人情報、実在人物への攻撃を採点せず終了する条件。
4. 結果画像を公開できる範囲と、必要なクレジット。
5. BGMの制作方法、ライセンス、音量設定。

初回実装には固定お題120件、故障カード8件、3ステージ、3難易度、AI採点、結末と最小人間度の記録、合成効果音、通常設定に従う読み上げを含みます。残る採点再現性と実画面・実音声の確認は[未完了項目](TASKS.md)で管理します。
