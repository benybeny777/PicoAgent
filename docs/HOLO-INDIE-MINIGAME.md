# holo Indie応募のゲーム企画（検討メモ）

この文書は、holo Indieの審査で最大の未確定点になっている**「PicoAgentを、ファンが遊びたい作品としてどう見せるか」**を決めるための検討メモです。実装ルールではありません（ルール正本は[AGENTS.md](../AGENTS.md)、現行仕様は[SPEC.md](../SPEC.md)、取引条件は[IP-LICENSING-STRATEGY.md](IP-LICENSING-STRATEGY.md)）。企画は未実装で、採否も未決です。

## 0. 結論

- 第一候補は、従来の「実時間で進む物語」「デスクトップに滲み出す謎解き」「推しに調べさせる推理」を一本にまとめた**「AI相棒とデスクトップ事件簿」**です。
- 利用者は選択肢ではなく自由文で調査方針を伝えます。キャラは検索、資料読解、画像確認などのツールを実際に使い、根拠付きの調査ログを返します。**自由文の理解、道具の選択、資料をまたぐ推論、履歴に応じた進行**が遊びの中核であり、LLMを外すと成立しません。
- 初回審査ビルドは、10〜15分で完結する事件1本に絞ります。事件の正解と証拠は固定し、LLMは自由な指示を既存の証拠と行動へ結び付けます。毎回正解まで生成させる方式は、品質と監修を安定させにくいため採りません。
- 短い導入として「AI即興ステージ」、継続理由として「毎日の相棒ミッション」を組み合わせます。ただし、複数の小品を横並びにして主案をぼかしません。
- **無音は評価軸にも優先事項にもしません。** 審査版から外すのは、許諾のないタレント音声モデルとAivisによる読み上げです。権利処理済みのBGM、効果音、成功音、環境音はゲームの手応えを作るために使います。消音時もテキストと視覚演出で進行できるようにすることは、優先順位ではなくアクセシビリティと利用環境への対応です。

## 1. 企画を選ぶ基準

### 加点する基準

| 基準 | 確認すること |
|---|---|
| **LLMが不可欠か** | LLMを固定分岐へ置き換えたとき、遊びの価値が明確に失われるか |
| **PicoAgentらしいか** | 会話だけでなく、検索・資料読解・画像確認・履歴・常駐画面を遊びに使っているか |
| **すぐ伝わるか** | 審査する人が3分以内に「何が新しくて、何が楽しいか」を体験できるか |
| **ファン体験になるか** | 汎用AIではなく、推しと協力している感情的な価値があるか |
| **完成させられるか** | 概ね遊べる一本を、応募時期までに品質を落とさず作れるか |

### 合否を決める制約

- キャラ本人の台詞は脚本と監修済みテンプレートを正本にする。
- LLMの判断は証拠ID、行動ID、状態遷移などの構造化データにし、ゲーム状態はコード側が確定する。
- 外部検索や画面取得は、利用者が指示した範囲だけで実行し、何を参照したかを調査ログへ残す。
- 審査版は同梱ローカルLLMで始められ、API鍵を要求しない。
- 許諾のないタレント音声合成は含めない。BGM・効果音は権利と同梱条件を確認して使う。

制約は満たして当然の合格条件です。**制約を多く満たす案を、面白い案より上へ置きません。**

## 2. LLMの優位性をどう遊びにするか

| LLMの能力 | ゲーム内の体験 | 固定分岐だけの場合 |
|---|---|---|
| **自由文を理解する** | 「写真の時計と証言の時刻を比べて」のような利用者独自の方針で動く | 用意された選択肢しか試せない |
| **道具を選んで実行する** | 検索、資料内検索、画像確認を組み合わせて証拠を集める | 調査が台本上の演出になる |
| **複数資料を結び付ける** | 証言、画像、時系列の矛盾を仮説として整理する | 一問一答のクイズになる |
| **履歴から個人化する** | 以前の選択、得意な調査、進行状況を次の場面へ反映する | 誰が遊んでも同じ順番になる |
| **範囲内で内容を変える** | 寄り道の依頼、NPC資料、ヒントの出し方が変わる | 周回するとすべて既知になる |

「AIが自由にキャラを演じる」ことを優位性にはしません。**利用者の意図を理解し、実際に道具を使い、根拠を持ち帰ること**を優位性にします。

## 3. 第一候補：AI相棒とデスクトップ事件簿

### 遊びの流れ

1. キャラから短い脚本付きの依頼が届く。
2. 利用者が自由文で「まず何を調べるか」を伝える。
3. LLMが行動計画を構造化し、許可されたツールで資料、画像、必要に応じてWebを調べる。
4. 見つけた事実は、出典と証拠IDを持つ**調査ログ**へ追加される。キャラの台詞とは明確に分ける。
5. 利用者は集めた証拠を並べ、自由文で推理を提出する。
6. コード側が必須証拠と矛盾を検査し、LLMは推理の筋道を補助評価する。結末は脚本の状態遷移から選ぶ。

### 審査用の完成範囲

| 場面 | 実装するもの | 審査で示す価値 |
|---|---|---|
| **冒頭3分** | 指示を自由入力し、資料検索と画像確認を1回ずつ成功させる | 会話AIではなく、動けるAI相棒であること |
| **中盤** | 複数の証拠を調査ボードへ集め、矛盾を1つ見つける | LLMの資料横断と、利用者の推理が両方必要なこと |
| **終盤** | 推理を自由文で提出し、証拠不足なら追加調査、揃えば脚本済みの結末へ進む | 自由さと監修可能な物語を両立できること |
| **終了後** | 調査方針と結果を1枚の事件記録として保存する | 遊んだ人ごとの差と、共有したくなる成果物 |

事件の正解、必須証拠、禁止された結び付け、結末は固定データにします。審査版の基本事件は同梱資料だけで完結させ、外部Webの変化や通信障害で詰まらせません。Web検索を使う追加依頼は、一般版で明示許可を得たときだけ開きます。

### キャラとLLMの責務

| 表示主体 | 内容 | 生成方法 |
|---|---|---|
| **キャラ本人** | 導入、感情反応、節目の台詞、結末 | 脚本・監修済みテンプレート |
| **調査ログ** | 参照先、抜き出した事実、証拠ID、未確認点 | ツール結果から生成し、出典のない断定を拒否 |
| **事件資料・NPC** | 固定事件の文書と発言 | 監修済み固定データ。将来の寄り道だけ制限付き生成を検討 |
| **ゲーム状態** | 証拠取得、進行、成功・失敗 | コード側の決定論的な状態機械 |

この分離により、LLMの自由さを「本人の発言」へ背負わせず、調査能力へ集中できます。

## 4. 組み合わせる補助企画

| 優先 | 企画 | 役割 | LLMの必然性 | 判断 |
|---|---|---|---|---|
| **2** | **AI即興ステージ** | 起動直後の2〜3分で自由入力と反応の速さを見せる。大喜利と説得ゲームを同じ短編基盤へまとめる | 自由回答の理解と評価 | 事件簿の導入として1種だけ作る。採点の揺れを実機で許容できなければ外す |
| **3** | **毎日の相棒ミッション** | 集中タイマー、留守番、日替わり依頼を事件簿の進行や収集へ接続する | 履歴と利用者文脈による個人化 | 長期継続の説明に使う。審査ビルドでは1回分だけ見せる |
| **将来** | **AI配信ごっこ** | 視聴者コメントと企画進行が毎回変わる配信体験 | コメント生成、自由入力への追随 | ファン体験は強いが、台詞量と画面制作が重いので二手目 |
| **将来** | **デスクトップ・ボス戦** | 画面全体を使う派手な見せ場 | 現状は低い。敵や戦術が固定ならLLMは不要 | 映像映えは強いが、LLMの優位性を示す主案にはしない |

補助企画は独立したミニゲーム集にしません。事件簿の登場人物、進行、収集物を共有し、**一本の作品として続きが気になる構造**にします。

## 6. 音の方針

- 審査版には、配信・動画から学習した音声モデル、AIVMX、Aivis本体、音声用初期設定を含めません。キャラの台詞はテキストで表示します。
- BGM、操作音、証拠発見音、場面転換音、環境音は、作品のテンポと手応えに必要な範囲で入れます。自作または商用配布可能な素材に限定し、出所とライセンスを記録します。
- 全体音量、BGM、効果音を個別に調整でき、消音しても字幕と視覚演出で情報を失わない設計にします。
- 許諾後に本人収録の定型ボイスまたは公式許諾の音声モデルが提供された場合は、台詞イベントへ差し込める構造にします。初回審査の合否を、その提供へ依存させません。

## 7. 実装前に確定すること

1. 応募締切、提出物、外部通信、同梱ローカルモデルに関する最新の審査条件。
2. 審査用の固定事件で扱う題材、脚本、必須証拠、結末、監修単位。
3. 同梱ローカルLLMでの指示解釈、証拠ID抽出、推理補助評価の成功率と応答時間。
4. ツール実行前の許可、調査ログの保存期間、事件記録を公開できる範囲。
5. BGM・効果音の制作方法、ライセンス、クレジット表示。
6. 本体無料・キャラ課金の方針と、holo Indie版の販売・還元方式の整合。
7. キャラ本人の台詞、NPC、調査ログを審査側がどの単位で確認するか。

実装開始時は、まず固定事件の資料と状態機械を作り、次にローカルLLMの構造化出力とツール実行を接続します。自由生成を増やすのは、事件1本が再現可能に完走してからです。
