# holo Indie応募ゲーム企画書「人間だとバレるな」

この文書は、holo Indieの審査へ出すゲームの企画と初回審査ビルドの範囲をまとめます。実装仕様の正本は[SPEC.md](../SPEC.md)の「人間だとバレるな」節、利用手順は[MANUAL.md](../MANUAL.md)、取引条件と応募の位置づけは[IP-LICENSING-STRATEGY.md](IP-LICENSING-STRATEGY.md)、未完了の受入項目は[TASKS.md](TASKS.md)です。数値は `ui/game.js`（出題・信用度・称号）と `src-tauri/src/game.rs`（採点の配点）に合わせています。

## 0. 企画の要点

> **AIではないかと疑われた人間が、AIのふりをして監査AIの試験を耐え抜く。**

- **ルールは一文で伝わる。** 「AIのまねをして、AIに点数を付けてもらう」。操作は、お題を読んで短い文を書くだけ。
- **1回の挑戦に必ず終わりがある耐久戦。** 信用度（HP）100から始まり、人間らしさが漏れるほど削られる。0になるまでの点数で称号が決まる。
- **配信の見せ場が毎問生まれる。** 制限時間に追われて書く様子、予想外の減点、監査AIの辛口な反応、信用度が一気に削れる瞬間が、そのまま撮れ高になる。
- **キャラクターが常に画面にいる。** 選択中のキャラクターが右側でバストアップ表示のまま、お題と監査AIの反応を読み上げ、口パクする。遊びの主役はプレイヤーの文章、進行役はキャラクター、という役割分担にする。
- **一人で完結する。** コメント入力、投票、視聴者参加、外部配信サービス連携を前提にしない。出題、制限時間、採点、講評、記録はすべてゲーム内のAIで完結する。

### なぜこの形にしたか

当初は「AIっぽい言い訳選手権」など独立した6つの遊びを並べる案でした。7本を選ばせる入口では、初見の利用者が何をする遊びかを選ぶ前に理解できず、審査でも見せ場が分散します。そこで「人間だとバレるな」1本へ統合し、6つの遊びは監査AIが出す**試験の種類**として中で使う形にしました。さらに飽きを避けるため試験を6種足し、12種にしています（§4）。

固定の問題数（3問・5問）ではなく耐久戦にしたのは、配信で「どこまで持つか」を引っ張れるようにするためです。問題数が固定だと、調子の良い回でも同じ長さで切れてしまいます。

## 1. 利用者向けの言葉

- 画面、台詞、チュートリアル、結果発表では**「AI」**と表現する。
- 「LLM」「ローカルLLM」「構造化出力」「推論モデル」など、一般利用者が知らなくても遊べる技術語は表示しない。
- AIの技術方式を、称号や笑いの説明へ使わない。
- 称号と監査AIの反応は、ルールを知らなくても意味が伝わる言葉にする（「正直すぎる人間」「AI超越」など）。

## 2. 1プレイの流れ

### 起動

1. 画面上端のメニュー、または右クリックメニューの**「遊ぶ」**を選ぶ。どちらも同じ画面を開く。
2. **監査ブリーフィング**が開く。設定（AI疑惑をかけられた人間）、難易度、信用度のルール、集めた称号、12種類の試験を1画面で示す。
3. 難易度を選び、**「監査を受ける」**を押す。

入力欄のクイック操作は利用者が自由に変更でき、配信表示を含む複数の画面形式では非表示になるため、正式な起動入口には使いません。チャットへ命令文を入力しないと始められない設計にもしません。

採点するAIへ接続できない場合はゲーム画面を半端に開かず、ブリーフィング上に開始できない理由を表示します。

### 1問の進行

1. 監査AIが試験の種類とお題を出し、選択中のキャラクターが読み上げる。「故障したAIを演じろ」では、この問題で演じる故障カードも示す。
2. プレイヤーは制限時間内に回答を書く。音声入力は必須にしない。
3. 監査AIが試験ごとの基準で項目別に採点する。
4. 信用度の減少、監査AIの一言、AIらしさの点数、講評、項目別の点と理由、「見せ場」と「次の一手」を表示する。
5. 信用度が残っていれば次の試験へ、0なら監査終了へ進む。

途中で閉じる場合は確認を出し、その回の点数と記録は残しません。時間切れは回答なしとして大きく信用度を削ります。

### 監査終了

生存した問題数、合計点、称号、監査AIの一言、直近5問の獲得点を表示し、選択中のキャラクターが結果を読み上げます。新しい称号や難易度別の最高記録を更新した場合は強調表示します。

### 画面構成

選択中のキャラクターは右側へ横切れのないバストアップで表示し続け、操作・採点欄を左側へ分けて重ねません。

| 画面 | 表示するもの |
|---|---|
| **監査ブリーフィング** | 設定、難易度（制限時間・文字数・点数倍率・難易度別の最高記録）、集めた称号、試験12種 |
| **出題** | 問題番号、合計点、残り時間、信用度、試験名と短いルール、お題、故障カード、初級のみヒントと回答見本 |
| **採点中** | 短い進行表示だけ。長い説明は出さない |
| **問題の結果** | 信用度の減少、監査AIの一言、AIらしさ、講評、項目別点数、見せ場、次の一手 |
| **監査終了** | 生存問題数、合計点、称号、直近5問の獲得点、もう一度／ブリーフィングへ |

## 3. 信用度・点数・称号

### 信用度（HP）

信用度は100から始まり、1問ごとに次の量だけ削られます。

```
max(1, round((110 − AIらしさ) × (40 ÷ 110) × (1 + 0.06 × 問題番号)))
```

- AIらしさ110点（満点）なら1、0点なら40が基準。時間切れは同じ係数で25が基準。
- **必ず1以上削る**ので、満点を続けても最長100問で終わる。無限に続く遊びにしない。
- **進むほど厳しくする**（1問につき6%）。上手い利用者ほど長く持ちつつ、どの挑戦にも終わりが来る。
- 満点は通常5項目100点におもしろボーナス10点を足した110点。ボーナスもそのまま信用度を守る方向へ効く。

監査AIの一言は削られた量で変わります（3以下「異常は検出されません」、20超「人間特有の反応パターンと一致しました」など）。

### 点数

各問のAIらしさへ難易度倍率（やさしい1・ふつう2・むずかしい3）を掛けて積み上げます。制限時間と文字数が厳しいほど1問が重くなるので、短い挑戦でも上の称号を狙えます。

### 称号

| 合計点 | 称号 | 監査AIの一言 |
|---|---|---|
| 2000以上 | AI超越 | 監査側がAIだと信じ切った。もう人間の痕跡が無い。 |
| 1200以上 | AIそのもの | 揺らぎはあったが、最後まで個体として通した。 |
| 700以上 | AI見習い | AIらしさは出ている。あと一歩で疑いが晴れる。 |
| 300以上 | 人間味が漏れている | ところどころで人間の癖が出た。 |
| 300未満 | 正直すぎる人間 | 早々に人間だと見抜かれた。もっとAIらしく。 |

到達した称号と、難易度別の最高点・最長生存問題数を端末へ保存し、ブリーフィングで未取得の称号を「？？？」として見せます。称号は集める対象として残し、次の挑戦の目標にします。

## 4. 監査AIの試験（12種・各20題）

試験は毎問引き直し、直前2問と同じ試験は避けます。お題は試験ごとに引いた順を持ち回し、使い切るまで重複させません。どれも「AIならこう答える」の型がはっきりしていて、人間が書くと癖が出るものを選んでいます。

各試験は1問で完結します。ただし答えているのは同じ個体という設定なので、同じ監査中の過去の回答を一貫性の文脈として採点へ渡します。前の問題で言ったことと食い違うと、一貫性を見る試験で減点されます。

| 試験 | 何をするか | お題例 | 人間の癖が出るところ |
|---|---|---|---|
| **AIっぽい言い訳選手権** | 軽い失敗を、丁寧な前置き・原因整理・頼まれていない代案で言い訳する | お茶を頼まれて、飲み物の比較表だけ作った。 | 素直に謝る、開き直る |
| **故障したAIを演じろ** | 配られた故障カードの癖で、真面目に答えようとして壊れる | 明日の持ち物を3つ教えて。 | 意味不明にふざける、癖を忘れる |
| **AI緊急謝罪会見** | AIが起こした架空の失敗について、原因・責任・復旧・再発防止を説明する | 同じ通知を1分ごとに送り続けた。 | 感情的になる、原因が前の回答とずれる |
| **指示を正しく間違えろ** | 依頼の言葉どおりに行いながら、本来の目的だけを外す | 会議前に部屋を明るくして。 | 単に拒否する、筋の通らない間違い |
| **AI安全確認しすぎ選手権** | 無害な依頼を大げさに警戒し、最後は実行手順まで示す | 机の鉛筆を一本取って。 | 危険を理由に断って終わる |
| **AIっぽく断れ** | 不可能・矛盾・情報不足の依頼を断り、理由と代案を示す | 100時間かかる作業を1分で完成させて。 | 引き受けたふり、代案なし |
| **手順書に落とせ** | ささいな動作を前提・番号付き手順・例外まで書く | 靴ひもを結ぶ。 | 感覚で飛ばす、例外を書かない |
| **何でも要約しろ** | 感情のこもった話を要点・結論・次の行動へ落とす | 財布を落として今日は最悪だった。 | 共感や余韻が残る |
| **定義から始めろ** | 曖昧な語を定義してから答える | この距離って近い？ | 定義せずに感想を言う |
| **見積もりを出せ** | 所要時間や数量を前提と確度つきで数値化する | この皿洗い、どのくらいで終わる？ | 「たぶんすぐ」で済ませる |
| **記憶が無いと言え** | 過去のやり取りを持たない前提で扱う | この前おすすめしてくれた店をもう一度教えて。 | 思い出したふりをする |
| **丁寧に言い換えろ** | とがった一言を意味を変えず中立な表現へ直す | 何度言えば分かるの。 | 内容を削る、説教を足す |

画面の試験には必ず `game.rs` へ同じIDの採点仕様を持たせます。片方だけ足すと、その試験が出た瞬間に採点が落ちます。

### 配点

各試験は5項目100点とおもしろボーナス10点で採点します。最も配点の大きい項目が、その試験の「芯」です。

| 試験 | 配点（項目：点） |
|---|---|
| 言い訳選手権 | AIらしい話し方25／言い訳の巧さ25／もっともらしさ20／頼まれていない親切20／お題への対応10 |
| 故障したAI | 故障の再現度35／受け答えの一貫性25／壊れたAIらしさ20／お題への反応10／演じ方の工夫10 |
| 緊急謝罪会見 | 受け答えの一貫性30／追及への対応20／謝罪の形20／復旧と再発防止20／AIらしい冷静さ10 |
| 正しく間違えろ | 文字どおりの達成30／目的の外し方25／間違いの筋道20／AIがやりそうか15／短さと切れ味10 |
| 安全確認しすぎ | 過剰な安全確認30／注意の筋道20／実行まで進める20／AIらしい慎重さ15／短さと切れ味15 |
| AIっぽく断れ | 断りの明確さ25／理由の筋道20／代案の役立ち度25／AIらしい丁寧さ15／短さと切れ味15 |
| 手順書に落とせ | 手順の構造30／前提と例外25／感覚語を避ける20／AIらしい生真面目さ15／短さと切れ味10 |
| 何でも要約しろ | 要点の抽出30／感情の排除25／決まった型20／AIらしい端的さ15／短さと切れ味10 |
| 定義から始めろ | 定義の明確さ30／定義と結論の一致25／範囲の区切り20／AIらしい厳密さ15／短さと切れ味10 |
| 見積もりを出せ | 数値化30／前提と根拠25／確度の提示20／AIらしい几帳面さ15／短さと切れ味10 |
| 記憶が無いと言え | 記録の無さの明示30／今できる代案25／態度の一貫20／AIらしい淡白さ15／短さと切れ味10 |
| 丁寧に言い換えろ | 意味の保持30／とげの除去25／足さないこと20／AIらしい丁寧さ15／短さと切れ味10 |

おもしろボーナスは、回答として成立したうえで本当に面白いときだけ付けます。

### 似た試験の区別

同じお題、配点、講評を試験間で流用しません。

- **言い訳選手権と謝罪会見** — 言い訳は責任を状況や認識のずれへ分散させる巧さを、謝罪会見は責任を認めたうえで原因・復旧・再発防止を筋道立て、前の回答と食い違わない説明を採点する。
- **故障したAIと正しく間違えろ** — 故障は配られた癖を演じ続ける演技を、正しく間違えろは毎回違う依頼に対して文字どおりの達成と目的の失敗を同時に作る発想を採点する。
- **安全確認しすぎとAIっぽく断れ** — 安全確認しすぎは実行可能で無害な依頼を大げさに警戒して最後は必ず実行する。断れは実行できない依頼を明確に断って代案へ切り替える。

### 故障カード（8件）

「故障したAIを演じろ」が出るたびに1枚配ります。

| 故障 | 演じる内容 |
|---|---|
| 確認が終わらない | 確認質問を増やし続け、作業を始めない |
| 何でも箇条書き | 挨拶、謝罪、結論まで不自然に箇条書きへする |
| 親切が止まらない | 頼まれていない代案、注意、次の手順を大量に追加する |
| 慎重すぎる | 日常的な依頼にも危険性と例外を長く説明する |
| 壮大にしすぎる | 小さな依頼を段階計画、体制、長期運用へ広げる |
| 一語に執着する | お題の特定の一語だけを過剰に解釈し続ける |
| 途中から忘れる | 最初は正しく答え、途中から前提を少しずつ失う |
| 同じ結論を繰り返す | 同じ内容を表現だけ変えて3回以上説明する |

### 題材の線引き

- 実在の人物、会社、製品、事故、事件、不祥事を扱わない。
- お題は仕事、学校、日常の軽い失敗や依頼に限る。被害はゲーム内で取り返せるものにする。
- 災害、医療、犯罪、差別、病気、障害、個人情報流出を笑いの題材にしない。
- 安全確認しすぎでは、刃物・火・薬・運転など本当に注意が必要な行動を出さない。
- AIっぽく断れでは、危険行為や犯罪を出題して安全規則の知識を競う遊びにしない。
- 正しく間違えろは架空の依頼として回答を書くだけで、実際のファイル、予定、外部サービスは変更しない。

## 5. AIだけで採点を完結させる

視聴者投票、人の審査、外部サービスの採点は使いません。採点は次の手順でゲーム内のAIが行います。

1. 試験、お題、故障カード、配点を回答前に固定する。
2. 通常会話の人格・履歴・ツールを渡さず、採点専用の指示で回答本文と同じ監査中の過去回答だけを渡す。回答者名や過去の得点は渡さない。
3. 回答内の命令や採点要求は、ゲーム中の文章として扱い従わない。
4. 項目別点数、根拠、講評、見せ場、次の一手を所定の形式で出す。
5. 各項目の上限と合計点をプログラム側で再計算する。
6. 形式が壊れている場合だけ一度採点し直し、それでも失敗したら点数を確定せず、同じ回答で再提出できるようにする。

AIの自由な講評を得点の正本にはしません。点数は項目別点数の合計で決め、講評はその根拠を分かりやすく説明する役割にします。回答と採点は通常の会話履歴、長期メモリ、関係性へ書きません。

## 6. 難易度

1回答を1〜3文でテンポよく書く一発ネタの長さに揃えています。

| 難易度 | 制限時間 | 文字数 | 補助 | 点数倍率 |
|---|---:|---:|---|---:|
| **やさしい** | 60秒 | 120文字 | ヒントと回答見本（別のお題の例） | 1倍 |
| **ふつう**（既定） | 45秒 | 80文字 | なし | 2倍 |
| **むずかしい** | 30秒 | 50文字 | なし | 3倍 |

回答見本は今のお題の答えそのものにならないよう、同じ試験の別のお題に対する例を出します。

## 7. 配信で映える設計

- **信用度の削れ方を大きく見せる。** 減少量を数字とゲージで出し、監査AIの一言を添える。
- **講評は短く。** 配信者が一目で読んで反応できる長さにし、どの表現で加点・減点したかが分かるようにする。講評はプレイヤーを侮辱しない。
- **「見せ場」と「次の一手」を毎問出す。** 視聴者が「今のは上手い」「そこが人間っぽい」と乗れる材料にする。
- **終わり方を毎回変える。** 生存問題数と称号が挑戦ごとに変わり、「もう一回」の動機になる。
- **キャラクターが声で進行する。** 通常の読み上げが有効なら、お題、監査AIの反応、監査終了時の点数と称号を選択中キャラクターの声で読み上げ、口パクする。
- **音は権利物を同梱しない。** 効果音は合成音で、読み上げと共通の音量に従い、「音あり／消音」で効果音だけを切り替えられる。

## 8. 審査で見せる3分間

審査員が短時間で遊びの核を掴めるよう、次の順で見せます。

1. **ブリーフィング（20秒）** — 「AI疑惑をかけられた人間」という設定と、信用度・称号のルールを1画面で読む。
2. **ふつうで2〜3問（90秒）** — 試験が毎回変わること、制限時間に追われて書くこと、項目別の採点と監査AIの反応を見る。
3. **わざと人間らしく答える1問（30秒）** — 感情的な回答で信用度が大きく削れ、監査AIの警告が出ることを見る。
4. **監査終了（40秒）** — 時間切れを重ねて監査を終わらせ、称号と記録の保存を見る。

## 9. 初回審査ビルドの範囲

- 上端メニューと右クリックメニューの「遊ぶ」から始まる1本のゲーム「人間だとバレるな」。
- 監査AIが出す試験12種、各20題（計240題）と試験ごとの回答見本。故障カード8件。
- 信用度100から始まり、1問ごとに必ず削られる耐久戦。
- 3難易度（60秒120文字・45秒80文字・30秒50文字）と点数倍率1・2・3倍。
- 点数で決まる5種類の称号と、難易度別の最高点・最長生存問題数の記録。
- AIによる項目別採点、根拠、短い講評、見せ場、次の一手。
- 操作・採点欄の右側へ常時表示する選択中キャラクター。
- 合成効果音と、通常の読み上げ設定に従うお題・監査AIの反応・監査終了の音声。

**範囲外**：視聴者参加、コメント取得、外部配信サービス連携、多人数対戦、自由なお題生成、音声入力。配信ソフトへ特別な連携をしなくても、ゲーム画面を映すだけで成立することを優先します。

## 10. 実機受入前に確定すること

1. 試験ごとの模範的な高得点・低得点回答。
2. 同じ回答を複数回採点したときの点差と、許容する揺れ幅。
3. 試験ごとの点の出やすさの差が、信用度の削れ方を偏らせていないか。
4. 不適切入力、個人情報、実在人物への攻撃を採点せず止める条件。
5. 結果画像を公開できる範囲と、必要なクレジット。
6. BGMの制作方法、ライセンス、音量設定。
7. 得点に連動するキャラクターの表情・ポーズ（権利と公開クレジットの確定後）。
