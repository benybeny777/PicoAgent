# PicoAgent 販売戦略（クローズドソース・本体無料・キャラ買い切り）

この文書は「PicoAgent をどう売るか」を、実在の競合と価格アンカーに合わせて調整した検討メモです。実装ルールではありません（ルール正本は [AGENTS.md](../AGENTS.md)）。

**前提（確定事項）**

- **ソースは公開しない。** ビルドしたバイナリだけを配布する（OSS 化・オープンコアは採らない）。
- **本体は無料。収益源はキャラクターパックのみ**（2026-09 決定。§4）。
- **年商 1,000 万円未満**の個人／小規模事業者としての販売。

数字は 2026 年 8 月時点の公開情報に基づく想定で、契約前には必ず一次情報を確認してください。

## 1. 何を売るのか（現状の資産）

| 資産 | 内容 | 競合優位性 |
|---|---|---|
| ローカル完結の推論 | llama-server同梱・初回だけGGUFを取得・以後オフライン | 既定構成だけでローカル推論でき、OllamaやクラウドAIも選択可能 |
| 実務スキル 74 種 | Gmail / Slack / Google Workspace / GitHub / Notion / AI Drive / Office成果物 / 永続ジョブ / コード実行 | 「かわいいだけ」の競合が持っていない層 |
| キャラクター体験 | 透明ウィンドウ常駐・Live2D・読み上げ・ふれあい・関係性の記録 | 「実務だけ」の競合が持っていない層 |
| 安全設計 | 許可ルート・物理削除禁止・シークレット暗号化・設計ガード群 | 法人へ売るときの唯一の説得材料 |
| ローカル API / MCP | 外部ツールから叩ける・MCP サーバ／クライアント両対応 | 開発者層の入り口 |
| **キャラ拡張性** | ユーザーが自分の Live2D モデル／独自2.5Dパックを追加できる | **本製品の看板**。A 群は公式 IP の DLC しか選べず、B 群はできるが導入が難しい |

**一行の売り文句（案）**
> **推しを住まわせて、実務まで任せる。** クラウドに出さない、デスクトップ常駐の AI エージェント。

「自分のキャラを入れられる」は、A 群（公式 IP の DLC を買うだけ）に対する最も分かりやすい優位で、購入理由になりやすい要素です。ただし Live2D では**ライセンス上の必須手続き**が伴います（§3 参照）。

## 2. 競合マップ

PicoAgent は 1 つの市場ではなく、4 つの隣接市場の**交差点**にいます。それぞれ「勝てる点」と「勝てない点」が違うので、価格も訴求もその交差点に合わせて調整します。

| 群 | 代表 | 価格 | 強み | PicoAgent が勝てる点 | 勝てない点 |
|---|---|---|---|---|---|
| **A. デスクトップマスコット** | Desktop Mate（Steam 無料 + キャラ DLC 2,200 円）、Shimeji、VTube Studio | 無料〜2,200 円/キャラ | 圧倒的な認知・公式 IP（初音ミク等）・3D 品質 | 実務ができる（この群は会話も作業もほぼ無い） | キャラ IP の魅力・3D 表現・既存ユーザー数 |
| **B. OSS AI コンパニオン** | Open-LLM-VTuber（GitHub 12k★）、AITuberKit | 無料 | ローカル完結・Live2D・音声対話・熱心なコミュニティ | インストーラ一発・実務スキル数・安全境界・法人適性 | 価格（無料）・カスタマイズ自由度・「ソースが見える」信頼感 |
| **C. 汎用 AI アシスタント** | ChatGPT / Claude / Copilot / Perplexity | 月 20 ドル前後 | モデル品質・ブランド・エコシステム | ローカル完結（外部送信なし）・常駐キャラ・買い切り | 生の回答品質。ここは正面から戦わない |
| **D. ローカル LLM ツール** | LM Studio、Ollama、Open WebUI | 無料 | 開発者に浸透済み | 非開発者がそのまま使える体験・スキル・キャラ | 無料・モデル運用の柔軟性 |
| **E. ハード型相棒** | Gatebox、卓上 AI ロボット | 数万〜十数万円 | 存在感・話題性 | 価格・PC 上で実務まで届く | 物理的な「居る感」 |

### 空白地帯

- A は**かわいいが働かない**。B は**働きかけるが導入が難しく、スキルが薄い**。C は**働くがクラウドに出るしキャラがいない**。D は**開発者専用**。
- **「キャラが常駐して、ローカルで、実務スキルまで持ち、インストーラ一発」はどこも埋めていません。** ここが PicoAgent の唯一のポジションです。訴求は「かわいい AI」ではなく **「働く相棒」** に寄せ、かわいさは差別化ではなく**継続利用の理由**として扱います。

### クローズドソースで戦う場合の追加論点

B 群（OSS）に対して「ソースが見えない」不利が生じます。ここは正面から埋めず、**別の信頼の作り方**で置き換えます。

1. **通信の透明性** — 「ローカルモデル選択時は外部送信ゼロ」を、設定画面の通信ログ／診断タブで**ユーザー自身が確認できる**形にする。ソースを見せる代わりに挙動を見せます。
2. **本体が無料なので、買う前に全部試せる。** キャラ・会話・ローカルAI・実務スキルを実機で確かめたうえで、気に入ったキャラだけを買う形になります（§4）。
3. **配布元の明示と将来のコード署名** — 初期Windows版は未署名警告と正規配布URLを事前表示し、将来コード署名を導入した段階では発行元表示も信頼材料にします。

### Live2D 拡張性アプリケーションの扱い（B3 の詳細）

**「ユーザーが自分の Live2D キャラを追加できる」を売りにする＝拡張性アプリケーションとして契約する、と決めることと同義です。** 逃げ道はありません。

| 事実 | 内容 |
|---|---|
| 定義 | SDK を使い、ファイルやデータの追加・組み合わせで**不特定多数のモデルを扱える**アプリ（アバターシステム等）。PicoAgent のキャラ追加機構はこれに当たる |
| 免除 | **適用外。** 年商 1,000 万円未満でも、通常の作品に適用される免除はここには及ばない |
| 手続き | 事前の**審査**＋拡張性アプリケーション向けの出版許諾契約。通常の派生作品とは契約条件そのものが別 |
| 費用 | 公開されていない。要問い合わせ |
| **前例** | **VTube Studio**（個人開発・本体無料＋機能 DLC 課金）が正式にライセンスを受けて運営されている。**個人規模でも通る道があることの証明**で、収益モデルも PicoAgent の想定に近い |

**進め方**

1. **今すぐ申請を出す**（費用と条件が分からないまま計画を立てても意味がないため）。審査待ちの間に開発を止めない。
2. **審査待ちの間は、連番フレームのキャラパックで「自分で追加できる」を先に出荷する。** `cargo xtask character-pack validate / install` の仕組みが既にあり、Live2D を使わない限りライセンス上の制約はありません。看板の「自分のキャラを入れられる」は**この時点で既に成立します**。
3. Live2D 対応は承認後に有効化する（機能フラグで出し分け）。

### サンプルモデル（ひより／Haru／Epsilon）の扱い

**結論: 年商 1,000 万円で切り替えるのではなく、製品ビルドには最初から入れない。**

まず、1,000 万円という線が効く範囲を分けて捉える必要があります。

| 対象 | 1,000 万円の線 |
|---|---|
| **Cubism SDK** | 拡張性アプリケーションとして契約する以上、**この線は最初から関係ない**（免除が及ばない枠なので、契約条件がそのまま適用される） |
| **サンプルモデル（無償マテリアル）** | 線が効くのはこちら。1,000 万円未満なら商用利用可、超えると別途許諾が要る |
| **素材データの再配布** | **売上規模とは別の話。** インストーラにモデルデータを入れて配ることは、1,000 万円未満でも避けるべき性質のもの |

つまり「1,000 万円を超えたら抜く」という設計は、**再配布という別の論点を売上の線に紐づけてしまっている**ぶん、判断が 1 つずれています。加えて、切り替え方式そのものに実務上の難点が 3 つあります。

1. **超えたことは会計年度が締まってから分かる。** 直近会計年度の売上高で判定される以上、線を跨いだ事実は事後的に判明します。「超えた瞬間に差し替える」運用は原理的に成立しません。
2. **既に配った版は回収できない。** 差し替えの前に売れたインストーラにはモデルが入ったままで、その配布は済んでしまっています。
3. **切り替えが最も高くつくタイミングで切り替えることになる。** 1,000 万円を超えた頃はユーザーが最も多く、ストアのスクリーンショット・紹介動画・README の画像もサンプルキャラで作られています。**販促素材の作り直しまで含めて、一番忙しい時期に一番大きな入れ替えが発生します。**

**そして最大の理由は商品力です。** キャラが売りの有償製品で、初回起動時の顔が他社の公式サンプルというのは、ブランドが立ちません。**自社キャラは法務の要請ではなく商品の要請**です。現行の独自2.5Dキャラは mugi / mugi-normal-lvs / rin / mai / sena / aoi / photoreal-prototype の7体で、最初から自社キャラで出せます。

**「手順だけ付ける」という発想自体は正しく、むしろ売りに転用できます。**

- サンプルモデルの導入手順は、**「Live2D キャラを自分で追加する」機能のチュートリアルそのもの**です。公式サイトから落として入れる流れを最初の体験にすれば、看板機能のオンボーディングとして機能します。妥協ではなく導線になります。
- 設定画面の「キャラクターを追加」から、公式配布元・利用条件へ繋ぎ、表示名とIDを入力してzip／フォルダを直接追加できるようにした。`character.json` はアプリが自動生成する。

**技術的な担保** — `cargo xtask build` と `build-distribution` はどちらも `distribution/release.json` の配布許可リストだけを同期する。サンプル取得は `live2d-samples` という明示コマンドへ分離し、手元にモデルが残っていても製品へ混ざらない。

## 4. 価格設計（本体無料 × キャラクター課金）

> **2026-09 方針変更。** 本体と実務スキルをすべて無料にし、**キャラクターパックだけを商品にする**。Free／Pro のフリーミアム（Pro 買い切り 4,800 円案）は採らない。判断材料と却下した案は [docs/IP-LICENSING-STRATEGY.md](IP-LICENSING-STRATEGY.md) §4 末尾。**有償版をまだ 1 本も販売していない段階での変更なので、既存購入者の移行は発生しない。**

### なぜ本体を無料にするか

1. **IP 許諾の交渉で決定的に効く。** 有料の本体があると、事務所からは「キャラを餌にアプリを売っている」構図に見える。**「収益源はキャラクターパックだけです」と言い切れる状態そのものが交渉材料**になる。
2. **分配の線引きが論点ごと消える。** 「そのキャラ目当てで本体も売れたはず」という、レベニューシェアで最も揉める交渉が発生しない。
3. **キャラ販売はユーザー数に比例する。** キャラで稼ぐと決めた以上、本体価格は普及を止める障害物でしかない。
4. **OSS 群（§2 の B 群）に対する価格の不利が消える。** 「無料 vs 4,800 円」で比較されなくなる。

**引き換えに失うもの — 実務スキル 74 種の収益化経路。** Gmail / Slack / GitHub 連携は開発原価が高いが、これを無料で配ることになる。**スキルは「売り物」から「キャラを買わせる装置」へ位置づけが変わる。** 常駐時間が伸びるほどキャラへの愛着と購入動機が上がる、という一本の線で説明する。

**最大のリスク — 収益が「売れるキャラがあるか」への一点賭けになる。** Desktop Mate のキャラ DLC が 2,200 円で成立しているのは、サンリオ・初音ミク・2B といった既知 IP が並んでいるからで、無名 IP のキャラ単体で同じ課金率は望めない。**自社キャラだけで走る期間をどれだけ短くできるかが、この設計の成否を決める**（§6）。

### 非公開本体と拡張エコシステム

本体ソースは公開せず、バイナリだけを無料で配布します。利用者による拡張は、本体コードの公開ではなく次の安定した外部仕様で受けます。

| 開く | 開かない |
|---|---|
| **キャラパック仕様**（`character.json` の書式・検証ツール・作り方ドキュメント・サンプル 1 体） | 本体ソース |
| **MCP 経由のスキル追加**（外部プロセスなので本体と分離できる） | 有償キャラパックの実体 |
| ローカル API の仕様 | ライセンス判定 |

これで「ユーザーがキャラを作って配布し合う」流れを、本体を公開せずに作れます。キャラ配布の文化は無料本体の集客と、有償キャラパック販売の双方に使います。

### アンカー

- Desktop Mate のキャラ DLC = **2,200 円** → 日本のデスクトップマスコット層が「キャラに払う額」の相場。**本製品の価格はここに合わせる**
- ChatGPT / Claude = **月 20 ドル** → 「AI に払う額」の上限アンカー。**この土俵には乗らない（本体が無料なので比較されない）**
- OSS 群（Open-LLM-VTuber / AITuberKit / Ollama）= **無料** → **同じ土俵に立つことで、機能と完成度だけで比較される**

### プラン

| プラン | 価格 | 含むもの | 狙い |
|---|---|---|---|
| **本体** | **0 円** | 本体・ローカルAI・**実務スキル 74 種すべて**・キャラ追加・読み上げ・ローカルAPI／MCP・お試しキャラ 1 体 | 普及そのものが商品の前提。**機能では課金しない** |
| **自社キャラパック** | **1,800〜2,200 円/体** | 自社 IP のキャラ（独自2.5D／Live2D）＋人格＋（あれば音声） | 販売開始時の主収益。Desktop Mate の DLC 価格に合わせる |
| **公式 IP キャラパック** | **1,800〜3,500 円/体** | VTuber 事務所等の公式キャラ。売上はレベニューシェア | 単価と話題性の主力。条件は [IP-LICENSING-STRATEGY.md](IP-LICENSING-STRATEGY.md) |
| **Business（将来案）** | 年 18,000 円/席案（5 席〜） | ポリシー配布、監査ログ、優先サポート | **キャラではなく統制とサポートに払う別商品**で、無料本体と共存する。実装と運用が揃うまで販売対象にしない |

**課金の原則** — 「**機能には払わせない。キャラに払ってもらう**」。旧方針の「キャラと会話するだけなら無料、外の世界に手を伸ばすなら有料」は撤回します。この一文が変わることで、`license::tool_requires_pro()` の境界は不要になります（**実装側の変更なので別作業**）。

**なぜキャラを 1,800〜2,200 円にするか** — Desktop Mate の DLC と横並びで比較されるため、ここを外すと「割高なマスコット」に見えます。公式 IP で音声が付く場合だけ 3,000 円台まで上げられます。

### 同梱する無料キャラを 1 体に絞る

現行は自社キャラ 7 体（mugi / mugi-normal-lvs / rin / mai / sena / aoi / photoreal-prototype）を全部同梱していますが、**全部無料のままではキャラに払う理由が消えます。** お試し 1 体だけを同梱し、残りは有償パックへ回します。

- どの 1 体を残すかは、**最初の体験として最も強い 1 体**で選ぶ（看板キャラ）。
- `distribution/release.json` の `includedCharacters` を絞る作業が必要です。**実装・配布側の変更なので別作業**とし、本メモでは方針だけ確定します。

### なぜキャラを買い切りにするか

**PicoAgent はユーザーの API 鍵かローカルモデルで動くため、事業者側に推論の変動費が発生しません。** 月額にする理由がなく、月額にすると月 20 ドルの ChatGPT と品質で直接比較されて負けます。キャラクターは「買って手元に置くもの」という理解が最も自然で、Desktop Mate の DLC と同じ形です。

### キャラパックの鍵（オフライン前提）

PicoAgent はオフラインで動くことが売りなので、**起動のたびにサーバへ問い合わせる方式は製品思想と矛盾します。** 本体が無料になったことで、鍵が要るのは**キャラパックだけ**になります。

- **署名済みライセンスキー方式**（実装済みの `PA1.` キーを流用） — 購入時にメールアドレス＋購入 ID を含む文字列へ Ed25519 で署名したキーを発行し、アプリ内の公開鍵で**完全オフライン検証**する。判定対象が「Pro かどうか」から「どのキャラパックを持っているか」へ変わります（**実装側の変更なので別作業**）。
- 認証サーバ、ハードウェア紐付け、オンラインアクティベーションは初期は入れない（サポート負荷が価格に見合わない）。
- 解析対策は現状の release profile（LTO / strip / panic abort）以上には投資しない。**2,200 円のキャラパックでクラックと戦っても採算が合いません。**

## 5. 販路（優先順）

OSS 動線が使えないぶん、**無料版そのものが唯一の集客装置**になります。

| 順 | 販路 | 手数料 | 何を売るか | 理由 |
|---|---|---|---|---|
| 1 | **BOOTH** | 販売時点の公式料率を確認 | キャラパック | 初期想定の主販路。日本のキャラ購買層と相性がよく、現行の署名済みキー発行運用をそのまま使える |
| 2 | **Steam** | 販売時点のSteamworks条件を確認 | 無料本体・キャラDLC | **Desktop Mateの隣に並ぶ発見経路**。公開前にSteamworks所有確認を共通entitlementへ接続する |
| 3 | **公開GitHub** | 無料 | Windows無料版・最新版情報・サポート文書 | ソースや第三者ソフトは置かず、正規ダウンロード元とアプリ内更新の正本に限定する |
| 4 | **Vector / 窓の杜** | 掲載時点の条件を確認 | Free版の紹介 | 買い切りのWindowsソフトを探す層への補助導線。初期二販路の運用が固まってから判断する |

**Microsoft Store は当面見送り** — 配信の制約（同梱バイナリ・子プロセス起動）が PicoAgent の構造と噛み合いません。

**GitHub の扱い** — private 化後は開発の置き場のみ。ただし**リリースページだけを公開リポジトリ（コード無し・バイナリと README だけ）**として別に持つのは有効です。

## 6. 実行順序

**Phase 0 — 売れる状態にする（〜2 か月）**

外部確認と人の判断が必要なものから先に動かします。本体private化、公開配布Repo、署名済みライセンスキー、第三者ソフト非再配布の実装は完了済みです。**Free／Pro の境界実装は本体無料化により不要になるため、キャラパック単位の判定へ作り替えます（別作業）。**

1. **Live2D 拡張性アプリケーションの申請**（B3。審査・契約参照が販売ゲートに残っている）。
2. EULA、プライバシー、返金・特商法表示を販売条件へ合わせ、専門家確認を完了する（B2 / B10）。
3. Aivis／Whisperの直接取得、Cubism Core、推論エンジン、販売キャラを実成果物で台帳化する（B4 / B6 / B7）。
4. クリーンWindowsで未署名警告、初回取得、更新、アンインストールを通し、販売ゲート4件を閉じる。
5. **キャラパック仕様の公開ドキュメント整備**（連番フレーム版はLive2D審査結果に依存せず案内できる）。
6. コード署名と更新署名は初期出荷後の改善候補とし、導入を決めた時点で販売設定の必須ゲートへ戻す（B8）。

**Phase 1 — 無料版で取る（2〜4 か月）**
1. Free版を公開GitHubとSteamで案内する。KPIはDL数ではなく **7日継続率**（マスコット系は初日で消される）。
2. 「ローカルで動く AI が Gmail を要約して Slack に投げる」動画を 1 本。A・B・D いずれの層にも刺さる唯一の見せ方。
3. Discord か X でユーザーの声を集め、**最初に有償化するキャラと、次に作るキャラの決定**に使う。

**Phase 2 — 有償化（4〜6 か月）**
1. **自社キャラパックの販売開始。** 同梱を 1 体に絞り、残り 6 体を有償パックへ回す。初期購入者には早期支援者価格（1,500 円案）を出す。
2. **公式 IP の許諾がこの時点で取れているかが勝負。** 取れていれば公式キャラを主力に据え、取れていなければ自社キャラだけで走ることになるので、§4 の「最大のリスク」がそのまま顕在化する。照会は Phase 0 から動かし続ける。

**Phase 3 — 法人（6 か月〜）**
1. 「機密文書をクラウドに出せない部署の AI」として Business 版。刺さるのは士業・医療・自治体・製造の設計部門。
2. 監査ログとポリシー配布が無いと商談が進まないので、Phase 2 中に着手。

## 7. 競合が動いたときの備え

| 想定 | 起きること | 打ち手 |
|---|---|---|
| **Desktop Mate が AI 会話を載せる** | A 群の大量のユーザーがそのまま会話体験へ移る | 会話では戦わない。**実務スキルと安全境界**へ寄せる。Desktop Mate は IP 提供元の制約で OS 操作権限を取りに行きにくく、そこが堀 |
| **Open-LLM-VTuber がスキルを増やす** | 無料版の優位が消える | 堀は「インストーラ一発」と「設計ガードに支えられた壊れなさ」。OSS が最も追いつきにくいのは**完成度**であって機能数ではない |
| **OS 標準 AI（Copilot 等）が常駐化** | C 群が無料で全 PC に載る | ローカル完結と**キャラクターへの愛着**が残る。関係性の記録・ふれあいは、機能ではなく乗り換えコストとして効く |
| **クラウド API の値下がり** | ローカル完結の価値が相対的に下がる | 価値の軸を「安い」から「**出さない**」へ固定する。法人向け訴求は最初からこちら |

## 8. まだ決まっていないこと

1. **Live2D 拡張性アプリケーションの契約条件** — 申請しないと費用も条件も分かりません。**ここが返ってくるまで、Live2D 版の価格は確定できない**（契約費用が固定費として乗る可能性がある）。申請が全計画のクリティカルパスです。
2. **キャラ IP への投資額** — 自社キャラの Live2D 外注は 1 体 15〜40 万円程度。連番フレーム（既存のパイプライン）なら大幅に安く、第 1 弾はこちらで十分戦えます。
3. **法人へ行くかどうか** — 行くなら監査ログ・ポリシー配布・サポート窓口が必要で、開発リソースの配分が変わります。個人向けだけなら Phase 3 を丸ごと落とせます。
