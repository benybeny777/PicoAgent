# PicoAgent 販売戦略（クローズドソース・買い切り前提）

この文書は「PicoAgent をどう売るか」を、実在の競合と価格アンカーに合わせて調整した検討メモです。実装ルールではありません（ルール正本は [AGENTS.md](../AGENTS.md)）。

**前提（確定事項）**

- **ソースは公開しない。** ビルドしたバイナリだけを販売する（OSS 化・オープンコアは採らない）。
- **年商 1,000 万円未満**の個人／小規模事業者としての販売。

数字は 2026 年 8 月時点の公開情報に基づく想定で、契約前には必ず一次情報を確認してください。

---

## 1. 何を売るのか（現状の資産）

| 資産 | 内容 | 競合優位性 |
|---|---|---|
| ローカル完結の推論 | llama-server 同梱・初回だけ GGUF を DL・以後オフライン | Ollama も Node も不要。導入は 1 バイナリ |
| 実務スキル 67 種 | Gmail / Slack / Google Workspace / GitHub / Notion / PDF / Office / 議事録 / スケジューラ / コード実行 | 「かわいいだけ」の競合が持っていない層 |
| キャラクター体験 | 透明ウィンドウ常駐・Live2D・読み上げ・ふれあい・関係性の記録 | 「実務だけ」の競合が持っていない層 |
| 安全設計 | 許可ルート・物理削除禁止・シークレット暗号化・設計ガード群 | 法人へ売るときの唯一の説得材料 |
| ローカル API / MCP | 外部ツールから叩ける・MCP サーバ／クライアント両対応 | 開発者層の入り口 |
| **キャラ拡張性** | ユーザーが自分の Live2D モデル／キャラパックを追加できる（`character.json` + `character-pack validate/install`） | **本製品の看板**。A 群は公式 IP の DLC しか選べず、B 群はできるが導入が難しい |

**一行の売り文句（案）**
> **推しを住まわせて、実務まで任せる。** クラウドに出さない、デスクトップ常駐の AI エージェント。

「自分のキャラを入れられる」は、A 群（公式 IP の DLC を買うだけ）に対する最も分かりやすい優位で、購入理由になりやすい要素です。ただし Live2D では**ライセンス上の必須手続き**が伴います（§3 参照）。

## 2. 競合マップ

PicoAgent は 1 つの市場ではなく、4 つの隣接市場の**交差点**にいます。それぞれ「勝てる点」と「勝てない点」が違うので、価格も訴求もその交差点に合わせて調整します。

| 群 | 代表 | 価格 | 強み | PicoAgent が勝てる点 | 勝てない点 |
|---|---|---|---|---|---|
| **A. デスクトップマスコット** | Desktop Mate（Steam 無料 + キャラ DLC 2,200 円）、Shimeji、VTube Studio | 無料〜2,200 円/キャラ | 圧倒的な認知・公式 IP（初音ミク等）・3D 品質 | 実務ができる（この群は会話も作業もほぼ無い） | キャラ IP の魅力・3D 表現・既存ユーザー数 |
| **B. OSS AI コンパニオン** | Open-LLM-VTuber（GitHub 12k★）、AITuberKit | 無料 | ローカル完結・Live2D・音声対話・熱心なコミュニティ | インストーラ一発・実務スキル数・安全境界・法人適性 | 価格（無料）・カスタマイズ自由度・「ソースが見える」信頼感 |
| **C. 汎用 AI アシスタント** | ChatGPT / Claude / Copilot / Perplexity | 月 20 ドル前後 | モデル品質・ブランド・エコシステム | ローカル完結（外部送信なし）・常駐キャラ・買い切り | 生の回答品質。ここは正面から戦わない |
| **D. ローカル LLM ツール** | LM Studio、Ollama、Open WebUI | 無料 | 開発者に浸透済み | 非開発者がそのまま使える体験・スキル・キャラ | 無料・モデル運用の柔軟性 |
| **E. ハード型相棒** | Gatebox、卓上 AI ロボット | 数万〜十数万円 | 存在感・話題性 | 価格・PC 上で実務まで届く | 物理的な「居る感」 |

### 空白地帯

- A は**かわいいが働かない**。B は**働きかけるが導入が難しく、スキルが薄い**。C は**働くがクラウドに出るしキャラがいない**。D は**開発者専用**。
- **「キャラが常駐して、ローカルで、実務スキルまで持ち、インストーラ一発」はどこも埋めていません。** ここが PicoAgent の唯一のポジションです。訴求は「かわいい AI」ではなく **「働く相棒」** に寄せ、かわいさは差別化ではなく**継続利用の理由**として扱います。

### クローズドソースで戦う場合の追加論点

B 群（OSS）に対して「ソースが見えない」不利が生じます。ここは正面から埋めず、**別の信頼の作り方**で置き換えます。

1. **通信の透明性** — 「ローカルモデル選択時は外部送信ゼロ」を、設定画面の通信ログ／診断タブで**ユーザー自身が確認できる**形にする。ソースを見せる代わりに挙動を見せます。
2. **無料版で確かめられる** — 買う前に本体がフルで動く（後述のフリーミアム設計）。
3. **コード署名** — 発行元が実在する事業者として表示されること自体が、OSS に対する信頼の代替になります。

### Live2D 拡張性アプリケーションの扱い（B3 の詳細）

**「ユーザーが自分の Live2D キャラを追加できる」を売りにする＝拡張性アプリケーションとして契約する、と決めることと同義です。** 逃げ道はありません。

| 事実 | 内容 |
|---|---|
| 定義 | SDK を使い、ファイルやデータの追加・組み合わせで**不特定多数のモデルを扱える**アプリ（アバターシステム等）。PicoAgent のキャラ追加機構はこれに当たる |
| 免除 | **適用外。** 年商 1,000 万円未満でも、通常の作品に適用される免除はここには及ばない |
| 手続き | 事前の**審査**＋拡張性アプリケーション向けの出版許諾契約。通常の派生作品とは契約条件そのものが別 |
| 費用 | 公開されていない。要問い合わせ |
| **前例** | **VTube Studio**（個人開発・本体無料＋機能 DLC 課金）が正式にライセンスを受けて運営されている。**個人規模でも通る道があることの証明**で、収益モデルも PicoAgent の想定に近い |

**進め方**

1. **今すぐ申請を出す**（費用と条件が分からないまま計画を立てても意味がないため）。審査待ちの間に開発を止めない。
2. **審査待ちの間は、連番フレームのキャラパックで「自分で追加できる」を先に出荷する。** `cargo xtask character-pack validate / install` の仕組みが既にあり、Live2D を使わない限りライセンス上の制約はありません。看板の「自分のキャラを入れられる」は**この時点で既に成立します**。
3. Live2D 対応は承認後に有効化する（機能フラグで出し分け）。
4. **保険として VRM を検討する余地はある** — three-vrm は MIT で、VRoid Studio で誰でもモデルを作れるため、拡張性の裾野は Live2D より広い。ただし 3D 描画へ寄るので既存の Live2D 実装資産（pixi-live2d-display）とは別線になる。Live2D の審査結果が悪かった場合の代替として頭に置く程度でよい。

### サンプルモデル（ひより／Haru／Epsilon）の扱い

**結論: 年商 1,000 万円で切り替えるのではなく、製品ビルドには最初から入れない。**

まず、1,000 万円という線が効く範囲を分けて捉える必要があります。

| 対象 | 1,000 万円の線 |
|---|---|
| **Cubism SDK** | 拡張性アプリケーションとして契約する以上、**この線は最初から関係ない**（免除が及ばない枠なので、契約条件がそのまま適用される） |
| **サンプルモデル（無償マテリアル）** | 線が効くのはこちら。1,000 万円未満なら商用利用可、超えると別途許諾が要る |
| **素材データの再配布** | **売上規模とは別の話。** インストーラにモデルデータを入れて配ることは、1,000 万円未満でも避けるべき性質のもの |

つまり「1,000 万円を超えたら抜く」という設計は、**再配布という別の論点を売上の線に紐づけてしまっている**ぶん、判断が 1 つずれています。加えて、切り替え方式そのものに実務上の難点が 3 つあります。

1. **超えたことは会計年度が締まってから分かる。** 直近会計年度の売上高で判定される以上、線を跨いだ事実は事後的に判明します。「超えた瞬間に差し替える」運用は原理的に成立しません。
2. **既に配った版は回収できない。** 差し替えの前に売れたインストーラにはモデルが入ったままで、その配布は済んでしまっています。
3. **切り替えが最も高くつくタイミングで切り替えることになる。** 1,000 万円を超えた頃はユーザーが最も多く、ストアのスクリーンショット・紹介動画・README の画像もサンプルキャラで作られています。**販促素材の作り直しまで含めて、一番忙しい時期に一番大きな入れ替えが発生します。**

**そして最大の理由は商品力です。** キャラが売りの有償製品で、初回起動時の顔が他社の公式サンプルというのは、ブランドが立ちません。**自社キャラは法務の要請ではなく商品の要請**です。既に mai / mugi / rin という自前のキャラ資産があるので、ここは最初から自社キャラで出せます。

**「手順だけ付ける」という発想自体は正しく、むしろ売りに転用できます。**

- サンプルモデルの導入手順は、**「Live2D キャラを自分で追加する」機能のチュートリアルそのもの**です。公式サイトから落として入れる流れを最初の体験にすれば、看板機能のオンボーディングとして機能します。妥協ではなく導線になります。
- 設定画面の「キャラクターを追加」から、公式配布元・利用条件へ繋ぎ、表示名とIDを入力してzip／フォルダを直接追加できるようにした。`character.json` はアプリが自動生成する。

**技術的な担保** — `cargo xtask build` と `build-distribution` はどちらも `distribution/release.json` の配布許可リストだけを同期する。サンプル取得は `live2d-samples` という明示コマンドへ分離し、手元にモデルが残っていても製品へ混ざらない。

## 4. 価格設計（フリーミアム × 買い切り）

### オープンコアか、フリーミアムか

**「機能で課金する」と「ソースを公開する」は別の話で、切り離せます。**

| | オープンコア | フリーミアム（推奨） |
|---|---|---|
| コアのソース | 公開する | 公開しない |
| 課金 | 上位機能 | 上位機能 |
| 配布 | ソース + バイナリ | バイナリのみ |

**課金構造はどちらも同じです。** 違いはソースを出すかどうかだけなので、**ソース非公開のまま機能課金は問題なくできます。** 推奨はフリーミアム、理由は 3 つ。

1. **オープンコアが効くのは「顧客が開発者」の製品** — GitLab や Sentry は、コードを読む人がそのまま導入決定者でした。PicoAgent の顧客は非開発者なので、星やフォークが売上に変換されません。
2. **バイパスが容易になる** — Rust の単一バイナリで、コアと有料機能は同一プロセスにあります。コアを公開すると**ライセンス判定の箇所がそのまま見える**。判定を 1 箇所に集約する設計（推奨どおり）だと、その 1 行を消したビルドを誰でも作れます。4,800 円の製品でこの防衛戦はできません。
3. **拡張性はソース公開なしで実現済み** — 「拡張できる」と「ソースが見える」は別物です。PicoAgent には既に**キャラパック機構**と **MCP サーバ／クライアント**があり、サードパーティ拡張はこの 2 経路で受けられます。

### エコシステムだけ開く（推奨形）

オープンコアの利点である「他人が作って広がる」だけを、ソースを出さずに取ります。

| 開く | 開かない |
|---|---|
| **キャラパック仕様**（`character.json` の書式・検証ツール・作り方ドキュメント・サンプル 1 体） | 本体ソース |
| **MCP 経由のスキル追加**（外部プロセスなので本体と分離できる） | 有料スキルの実装 |
| ローカル API の仕様 | ライセンス判定 |

これで「ユーザーがキャラを作って配布し合う」流れは起きます。**キャラ配布の文化ができれば、それ自体が無料版の集客装置**になり、OSS の星の代わりになります。自社キャラパックの販売とも共存します（VTube Studio はユーザーが自由にモデルを入れられる状態で DLC を売れています）。

### アンカー

- Desktop Mate のキャラ DLC = **2,200 円** → 日本のデスクトップマスコット層が「キャラに払う額」の相場
- ChatGPT / Claude = **月 20 ドル（年 約 36,000 円）** → 「AI に払う額」の上限アンカー
- OSS 群（Open-LLM-VTuber / AITuberKit / Ollama）= **無料** → 下限アンカー

### なぜ買い切りか

**PicoAgent はユーザーの API 鍵かローカルモデルで動くため、事業者側に推論の変動費が発生しません。** これは C 群に対する最大の武器で、**「月額ではなく買い切り」**という提示がそのまま差別化になります。逆に月額にすると、月 20 ドルの ChatGPT と品質で直接比較され負けます。

### プラン

| プラン | 価格 | 含むもの | 狙い |
|---|---|---|---|
| **Free**（無料版・バイナリ配布） | 0 円 | 本体・ローカルモデル・キャラ 1 体・基本スキル（時刻／天気／検索／ファイル／PDF／クリップボード等）・履歴 50 件まで | ソースを出さない代わりに**「動くもの」を無料で配って認知を取る**。OSS の星の代わりになる唯一の手段 |
| **Pro（買い切り）** | **4,800 円**（1 年間のアップデート込み、以後もその版を使い続けられる JetBrains 型） | 外部連携スキル（Gmail / Slack / Google Workspace / Notion / GitHub 等）、スーパーエージェント、スケジューラ、ローカル API / MCP サーバ、音声、キャラ全体 | ChatGPT 3 か月分未満、という言い方が効く価格帯 |
| **キャラパック** | **1,800〜2,200 円/体** | 自社 IP のキャラ（連番アニメ or Live2D）＋音声＋人格 | Desktop Mate の DLC 価格に完全に合わせる。比較時に割高に見えない |
| **Business** | **年 18,000 円/席**（5 席〜） | Pro 全機能＋ポリシー配布（許可ルート／禁止スキルの一括設定）、監査ログ、優先サポート | ChatGPT Plus の約半額。「置き換え」ではなく「機密作業用に追加する」枠 |

**なぜ Pro を 4,800 円にするか** — 3,000 円未満は「マスコットアプリ」に見え、実務ツールとして信用されません。9,800 円を超えると「AI に 2 年分前払い」と受け取られます。日本の個人向け買い切りソフトで最も摩擦が小さいのは 3,000〜6,000 円帯で、その中で「ChatGPT 2 か月分」と言い切れる 4,800 円が説明しやすい位置です。

**Free と Pro の線引きの原則** — 「**キャラと会話するだけなら無料、外の世界に手を伸ばすなら有料**」。この一文で説明できる境界にすると、ユーザーが納得しやすく、実装上も外部連携スキル群をまとめて判定できます。

### 有料版の鍵（オフライン前提）

PicoAgent はオフラインで動くことが売りなので、**起動のたびにサーバへ問い合わせる方式は製品思想と矛盾します。**

- **推奨: 署名済みライセンスキー方式** — 購入時にメールアドレス＋購入 ID を含む文字列へ Ed25519 で署名したキーを発行し、アプリ内に埋め込んだ公開鍵で**完全オフライン検証**する。サーバ不要・ネット遮断環境でも動く。
- 認証サーバ、ハードウェア紐付け、オンラインアクティベーションは初期は入れない（サポート負荷が価格に見合わない）。
- 解析対策は現状の release profile（LTO / strip / panic abort）以上には投資しない。**買い切り 4,800 円の製品でクラックと戦っても採算が合いません。**

## 5. 販路（優先順）

OSS 動線が使えないぶん、**無料版そのものが唯一の集客装置**になります。

| 順 | 販路 | 手数料 | 何を売るか | 理由 |
|---|---|---|---|---|
| 1 | **自社サイト + Stripe / Lemon Squeezy** | 3〜5% | Free 配布・Pro・Business | 粗利最大。Lemon Squeezy は日本からでも海外消費税の代行をしてくれるので個人事業者と相性が良い。法人請求書に対応できるのはここだけ |
| 2 | **Steam** | 30% | Free 本体 + キャラ DLC | **Desktop Mate の隣に並べられる価値が、クローズド販売では特に大きい**（GitHub の代わりの発見経路）。手数料 30% なので実務機能の主販路にはせず、無料本体＋キャラ DLC の場として使う |
| 3 | **BOOTH / DLsite** | 5〜10% | キャラパック・Pro キー | 日本のキャラ購買層が既におり、決済とファン文化の相性が良い。キー販売にも使える |
| 4 | **Vector / 窓の杜** | 0（掲載） | Free 版の紹介 | 「買い切りのローカル AI ソフト」を探す層に古典的だが確実に効く。法人の稟議でも通しやすい |

**Microsoft Store は当面見送り** — 配信の制約（同梱バイナリ・子プロセス起動）が PicoAgent の構造と噛み合いません。

**GitHub の扱い** — private 化後は開発の置き場のみ。ただし**リリースページだけを公開リポジトリ（コード無し・バイナリと README だけ）**として別に持つのは有効です。

## 6. 実行順序

**Phase 0 — 売れる状態にする（〜2 か月）**

外部の待ち時間があるものから先に動かします。1〜2 は着手が遅れるほど後工程が丸ごとずれます。

1. **Live2D 拡張性アプリケーションの申請**（B3。審査があり、費用も条件もこれが返るまで確定しない）。
2. **コード署名証明書の申請**（B8。リードタイムが最長）。
3. **リポジトリを private 化**（B1。今日できて、遅れるほど損をする）。
4. GPL 系ツールを初回取得方式へ（B6）。EULA・ライセンス表記画面（B2 / B4）。
5. **キャラパック仕様の公開ドキュメント整備**（看板機能。連番フレーム版は Live2D の審査結果に依存せず出せる）。
6. Free / Pro のスキル境界を実装。**判定は 1 箇所**（`config` のライセンス状態）に集約し、各スキルへ散らさない。
7. ライセンスキーの署名検証（B9）。

**Phase 1 — 無料版で取る（2〜4 か月）**
7. Free 版を自社サイト・Steam・Vector で公開。KPI は DL 数ではなく **7 日継続率**（マスコット系は初日で消される）。
8. 「ローカルで動く AI が Gmail を要約して Slack に投げる」動画を 1 本。A・B・D いずれの層にも刺さる唯一の見せ方。
9. Discord か X でユーザーの声を集め、Pro 同梱スキルの最終決定に使う。

**Phase 2 — 有償化（4〜6 か月）**
10. Pro 販売開始。初期購入者に早期支援者価格 3,800 円。
11. キャラパック 1 本目を BOOTH / Steam DLC で同時投入。Pro とキャラは購買層が違うので共食いしません。

**Phase 3 — 法人（6 か月〜）**
12. 「機密文書をクラウドに出せない部署の AI」として Business 版。刺さるのは士業・医療・自治体・製造の設計部門。
13. 監査ログとポリシー配布が無いと商談が進まないので、Phase 2 中に着手。

## 7. 競合が動いたときの備え

| 想定 | 起きること | 打ち手 |
|---|---|---|
| **Desktop Mate が AI 会話を載せる** | A 群の大量のユーザーがそのまま会話体験へ移る | 会話では戦わない。**実務スキルと安全境界**へ寄せる。Desktop Mate は IP 提供元の制約で OS 操作権限を取りに行きにくく、そこが堀 |
| **Open-LLM-VTuber がスキルを増やす** | 無料版の優位が消える | 堀は「インストーラ一発」と「設計ガードに支えられた壊れなさ」。OSS が最も追いつきにくいのは**完成度**であって機能数ではない |
| **OS 標準 AI（Copilot 等）が常駐化** | C 群が無料で全 PC に載る | ローカル完結と**キャラクターへの愛着**が残る。関係性の記録・ふれあいは、機能ではなく乗り換えコストとして効く |
| **クラウド API の値下がり** | ローカル完結の価値が相対的に下がる | 価値の軸を「安い」から「**出さない**」へ固定する。法人向け訴求は最初からこちら |

## 8. まだ決まっていないこと

1. **Live2D 拡張性アプリケーションの契約条件** — 申請しないと費用も条件も分かりません。**ここが返ってくるまで、Live2D 版の価格は確定できない**（契約費用が固定費として乗る可能性がある）。申請が全計画のクリティカルパスです。
2. **キャラ IP への投資額** — 自社キャラの Live2D 外注は 1 体 15〜40 万円程度。連番フレーム（既存のパイプライン）なら大幅に安く、第 1 弾はこちらで十分戦えます。
3. **法人へ行くかどうか** — 行くなら監査ログ・ポリシー配布・サポート窓口が必要で、開発リソースの配分が変わります。個人向けだけなら Phase 3 を丸ごと落とせます。
