# レビュー記録

コードレビューで出した指摘・修正提案を、**対応したものも見送ったものも**すべてここへ残す。
チャットの返答やコミットメッセージだけに書くと、次に作業する人（別のエージェント含む）が
「なぜそうなっているのか」「何が残っているのか」を追えなくなるため。

- 記録の単位は「レビュー1回」。新しい回は**上へ**追加する。
- 判定は `対応済み` / `見送り` / `保留` の3つ。**見送り・保留には必ず理由を書く**。
- 恒久ルールになったものは [AGENTS.md](../AGENTS.md)、仕様になったものは [SPEC.md](../SPEC.md) へ移し、ここには判定だけ残す。
- 進行中のブランチや環境の作りかたは [HANDOFF.md](../HANDOFF.md) の持ち場。ここは「判断の履歴」に絞る。

## 2026-08-07 — Live2D・起動画面・表示寸法まわりの事後レビュー

対象: `671865a`〜`4bcbd19`（Live2D 5.3互換、起動画面、8方向リサイズ、配信形式の拡大）
ブランチ: `claude/review-and-fix-pdvchm` / コミット: `35d7d67`（不具合修正）、`f5f3d7b`（改善提案の実装）

### 不具合として直したもの

| # | 指摘 | 判定 | 反映先 |
|---|---|---|---|
| 1 | 復元時の寸法下限が旧最小値 420×340 のままで、8方向リサイズで小さくした寸法が起動時に捨てられる | 対応済み | `lib.rs::restore_window_layout`。`layout::MIN_WIDTH/MIN_HEIGHT` へ統一し、`tauri.conf.json` との一致をテストで検出 |
| 2 | 起動準備中の共通寸法 680×430 を、その表示形式の寸法として記憶していた（待ち時間中の形式切替・設定保存で chat / widget の記憶が壊れる） | 対応済み | `layout.rs`。起動準備中は `remember_current_size()` を効かせない |
| 3 | 履歴の移行だけがロックを取り、`save()` / `clear()` は無ロック（＝ロックが機能しない） | 対応済み | `history.rs`。ロック名を `lock_name()` で共通化 |
| 4 | `is_simple_greeting` / `is_visible_on_any_monitor` が `#[cfg(test)]` 付きのテスト専用関数として残っていた（dead code） | 対応済み | 関数を削除し、テストは現行経路（`simple_greeting_answer` / `clamp_to_best_monitor`）へ付け替え |

### 改善提案として直したもの

| # | 提案 | 判定 | 反映先 |
|---|---|---|---|
| 5 | 起動時のクランプが、わざと画面端へはみ出して置いた定位置まで毎回引き戻す | 対応済み | `lib.rs::clamp_to_best_monitor`。掴める大きさ（80px）が残っていれば保存値のまま復元 |
| 6 | 短い挨拶の直接応答が全キャラ共通の定型文で、人格・口調を無視する | 対応済み | `agent.rs::simple_greeting_answer`。`character.json` の `greeting` を使い、時間帯を含まない挨拶（`hi` / やっほー）は実時刻で朝昼夜を選ぶ |
| 7 | 配信形式のキャンバス寸法 599×662px が立ち絵枠 285×315px の手計算で二重管理 | 対応済み | `renderer.js` の基準寸法を CSS 変数 `--char-frame-*` へ渡し、`--stream-canvas-scale` 倍で計算 |
| 8 | `index.html` の手書き `?v=…`（`styles.css` と `renderer.js` で版が食い違っていた） | 対応済み | `xtask/src/assets.rs::stamp_asset_versions`。`build-ui` が内容ハッシュで自動付与 |
| 9 | 起動画面表示中に設定保存・形式切替をすると、起動画面のまま小型形式へ縮む | 対応済み | `layout.rs::apply_unless_booting`。準備完了時の `pet_finish_boot` がまとめて当てる |

### 見送り・保留

| # | 内容 | 判定 | 理由 |
|---|---|---|---|
| 10 | Windows実機で、8方向リサイズ・端寄せ位置の復元・起動画面から保存形式への復帰を目視確認する | 保留 | GUI 起動が必要で自動検証できない。次に Windows 実機を触るときへ持ち越し |
| 11 | 各キャラで「こんにちは」「おはよう」「hi」の返答が自然か確認する（特に挨拶語で始まらない `rin` / `wanko` / `rice`） | 保留 | 文面の良し悪しは人が読んで判断する領域。ロジックとテストは入っている |
| 12 | 配信形式の立ち絵サイズが `calc()` 化で 0.5px 変わる（598.5px と 599px） | 保留 | 見た目に影響しない想定だが、実機で違和感が出たら `--stream-canvas-scale` を調整する |
| 13 | 起動時に `layout::apply()`（形式ごとの寸法）→ `restore_window_layout()`（全体の保存寸法）の順で二重に寸法を当てている | 見送り | 「手で決めた寸法を優先する」という現在の意図どおり。整理すると復元順の意味が変わるため、寸法の持ち方を決め直すときにまとめて扱う |
| 14 | 終了時保存が、起動画面表示中に閉じると 680×430 を `PICOAGENT_WINDOW_*_PX` へ書く | 見送り | 次回起動の一瞬だけ使われ、`pet_finish_boot` が保存形式の寸法へ戻すため実害が残らない |
| 15 | 起動が最後まで進まない環境（案内画面へ切り替わる等）では、#9 の保留により形式切替が次回起動まで当たらない | 保留 | 起動できていない状態なので実害は小さい。案内画面側の導線を作るときに合わせて検討する |
