# レビュー記録

コードレビューで出した指摘・修正提案を、**対応したものも見送ったものも**すべてここへ残す。
チャットの返答やコミットメッセージだけに書くと、次に作業する人（別のエージェント含む）が
「なぜそうなっているのか」「何が残っているのか」を追えなくなるため。

- 記録の単位は「レビュー1回」。新しい回は**上へ**追加する。
- 判定は `対応済み` / `見送り` / `保留` の3つ。**見送り・保留には必ず理由を書く**。
- 恒久ルールになったものは [AGENTS.md](../AGENTS.md)、仕様になったものは [SPEC.md](../SPEC.md) へ移し、ここには判定だけ残す。
- 進行中のブランチや環境の作りかたは [HANDOFF.md](../HANDOFF.md) の持ち場。ここは「判断の履歴」に絞る。

## 2026-08-08 — 2Dキャラ2倍化後の追加修正提案

対象: `8b87f46`。PNG系4キャラのPhotoshop仕上げ後に、配布容量・WebView読込・実解像度・制作工程を再点検した。実測は対象208枚・内容重複除外70画像・配置容量315.2MB・Git上の固有blob約104.9MB。`renderer.js::preloadAnimations()` は選択キャラの全アニメーションフレームを一括で `Image` へ読み込む。

| # | 優先 | 指摘・提案 | 判定 | 判断・実装方針 |
|---|---|---|---|---|
| 1 | P0 | **2倍画像の全フレーム一括プリロードを止める** | 保留 | 720×1280ならRGBA展開後は1枚約3.5MBで、42フレームを同時デコードすると画像キャッシュだけで約148MBになりうる。現在状態と次の2〜3枚だけを先読みし、キャラ切替時に旧キャラ参照を解放する。実装前後でWebViewのメモリと初回表示時間を計測する |
| 2 | P0 | **同一フレームの配置重複をなくして配布容量を抑える** | 保留 | Gitは同一blobを共有するが、配布物には208ファイル・315.2MBがそのまま入る。`character.json` に明示的なフレームパス配列または別名参照を追加し、70個の正本画像を複数アニメーションから共有する。まずPNG互換のまま重複だけを除き、WebP化は画質・CPU負荷を測って別判断にする |
| 3 | P1 | **補間拡大と本当の高精細化を分ける** | 保留 | 現在の2倍化は輪郭表示を安定させるが、HighQualityBicubicなので新しい描画情報は増えない。見た目をさらに上げるなら、70個の正本だけをPhotoshopスーパー解像度または比較可能なAIアップスケーラーへ通し、目・口・指・細線の形が変わらないものだけ採用する。生成塗りつぶしは背景除去で欠けた局所に限定する |
| 4 | P1 | **透過QAへ暗色背景と自動境界検査を追加する** | 保留 | ピンク／ミントは白残りを見つけやすいが、黒マットは見落としうる。白・濃紺・彩度色・チェッカーの4背景、半透明境界画素の色偏り、四隅アルファ、被写体bboxの急変を自動検査する。ポーズ共通の固定座標消去は今回欠けを作ったため使わない |
| 5 | P1 | **4キャラ×8表示形式を実画面で回帰撮影する** | 保留 | 素材単体の透過は確認済みだが、胸上／上半身の切れ方、字幕との重なり、起動中から通常表示への切替は実レイアウト依存。32組を撮影ツールで自動化し、基準画像との差分と目視一覧を残す。起動時間とピークメモリも同時記録する |
| 6 | P1 | **Photoshop工程を全件成功後にだけ反映する** | 保留 | 現行スクリプトはバックアップを取るが、後処理中に失敗すると一部だけ製品画像へコピー済みになりうる。全出力の読込・寸法・アルファ・件数を `temp/` で検証してから、キャラ単位で置換する二段階処理へ変える |
| 7 | P1 | **スクリプトが起動したPhotoshopを必ず終了する** | 対応済み | 既存Photoshopへ割り込まず起動中なら停止し、バッチが起動したCOMインスタンスは `finally` で終了・解放するよう修正した |

既存のアプリ全体提案では、上記の画像P0を終えた次に「キャラ構図の保存値検証とリセット意味の一本化」「Windows／macOS CI」を優先する。HTTP共通化や巨大ファイル分割は、その後の段階対応とする。
